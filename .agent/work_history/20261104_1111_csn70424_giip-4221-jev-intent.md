## 설계 결정 (근거 포함)

1. **② 를 `classifyRequest` 내부에 넣고 호출부 3곳은 `opts` 만 추가한다.**
   호출부 시그니처를 깨면 하위 호환이 깨진다 → 새 인자는 **선택 인자**(`opts = {}`)로 넣고,
   기존 2인자 호출 `classifyRequest(text, workDir)` 은 그대로 동작하게 했다.
   `isForceTaskCmd` 선평가 순서도 그대로다 — 명시적 의사는 모델 판정이 뒤집어도 안 된다.
2. **스위치 기본 OFF** — `JEV_INTENT_ENABLED` 미설정이면 ② 를 통째로 건너뛰므로 **판정 결과가 현행과 완전히 동일**하다.
   게이트웨이 배포가 아직 완료되지 않은 상태에서도 머지해도 트래픽이 없다.
3. **접속 주소는 환경변수 하나가 유일한 경로** — `GIIP_JEV_GATEWAY_URL`. 하드코딩 없음, 미설정 시 ③ 으로.
4. **임계값은 "확정"이 아니라 제안값의 자리표기자** — 기본 0.8/0.7/0.3 은 사양 §5 제안값을 그대로 복사한 것이고,
   평가(C) 전에는 확정값이 아니다. 코드·문서·로그 어디에도 확정으로 적지 않고, **전부 환경변수로 덮어쓸 수 있게** 했다.
   값은 **호출 시점**에 읽는다(모듈 로드 시점 상수로 잡으면 값 변경에 재시작이 필요하다).
5. **외부 응답은 보수적으로 파싱한다** — `intent` 가 `task`/`question` 이 아니면 고쳐 쓰지 않고,
   `intent_confidence` 가 유한한 수가 아니면 실패로 처리하고, 확률 필드 누락은 **0.0**(보수값).
   "분류값을 지어내면 봇이 그 값을 권위로 신뢰한다." 0.0 은 task 쪽으로 흐르지 않는다.
   라우팅 표에 없는 값(조회 여부 플래그 등)은 **로그에만** 남기고 판정에는 쓰지 않는다.
6. **판정 로그는 봇 프로세스 stdout(`console.log`)** — 새 저장소를 만들지 않는다.
   **원문은 남기지 않고** `maskString` 통과본의 sha256 앞 8 hex 와 길이만 남긴다.
7. **전송 계층을 주입 가능하게** — `opts.jevRequest` 로 Jev 전송 함수를, `opts.spawn` 으로 기존 LLM 호출을 갈아끼운다.
   그래서 회귀 테스트가 **네트워크 0** 으로 돈다. 상위 API 모듈을 `intent.js` 에 `require` 하지 않고
   Node 내장 `http`/`https` 만 쓰는 로컬 `postForm` 을 두었다(순환/결합 위험 회피).
8. **클라이언트는 본문을 자르지 않는다** — 길이 제한은 게이트웨이 규약의 몫이다.
   임의로 자르면 서버가 받은 값과 로컬 로그가 어긋난다.
9. **폴백 안내문은 ③ 가 실제로 실패했을 때만** 붙인다 — ③ 가 성공해서 `question` 이 나온 것은 정상 동작이다.
   붙이면 정상 동작을 오류처럼 보이게 한다.
