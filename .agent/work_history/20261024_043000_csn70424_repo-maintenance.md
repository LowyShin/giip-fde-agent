### T1-2 `test-lang-check.mjs` — 줄바꿈 커밋 본문이 Windows 에서 잘려 나가 검출이 0건이 된다

- **근본 원인(실측 재현)**: 테스트가
  `execSync('git commit -m "제목" -m "본문 첫째 줄\n본문 둘째 줄 中 있음"')` 로 커밋을 만든다.
  `\n` 은 JS 문자열 안에서 **실제 개행**이므로, 셸(cmd.exe)을 거치면 **명령이 개행 지점에서 잘려**
  커밋에 저장되는 메시지가 `"제목" + "본문 첫째 줄"` 까지만 남는다. 실측 `git log` 원문:
  ```
  4338e7c…\x1f제목\x1f본문 첫째 줄\n\x1e
  ```
  → "본문 둘째 줄 中 있음" 이 **커밋 자체에 없으므로** 검사할 대상이 없고, 메시지 검출이 **0건**이 된다.
  Linux(bash) 에서는 `\`+`n` 이 리터럴로 전달되어 이 문자가 그대로 남아 테스트가 통과하므로
  **Windows 전용 실패**였다.
- **조치**: 셸을 거치지 않는 `execFileSync('git', ['commit','-m',제목,'-m','본문 첫째 줄\n본문 둘째 줄 中 있음'])`
  로 변경(인자 배열 → 실제 개행이 git 에 그대로 전달). 같은 결함이 있던 2번째 지점
  (`다섯 번째` 커밋)도 함께 수정.
- **검증(Before/After)**: Before **73개 통과 / 1개 실패**(exit 1) → After **74개 통과 / 0개 실패**
  (`PASS test-lang-check`, exit 0). 수정 후 `git log` 원문에서 본문 2줄과 `中` 이 보존됨을 확인했다.
- **주의**: `checkGit` **구현**은 결함이 아니었다. `%H%x1f%s%x1f%b%x1e` 레코드 파싱과 `detect()` 은 정상 —
  **커밋 자체에 본문이 없었던 것**이 원인이다(구현을 건드리지 않았다).
