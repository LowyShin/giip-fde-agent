## 사전 조사 (코드 실측)

- **CJK-QA 2차 판정**(`Test-GissueCjkContamination`, 러너 잡 스코프): 호출부가 이미 이슈 세션의
  gair 계획(`$issueGairBaseUrl`/`$issueGairApiKey`/`$issueGairRequired`)을 같은 스코프에 갖고 있고
  함수도 `$Csn` 을 인자로 받는다 → **CSN 특정 가능**. 계획 전달 방식으로 적용.
- **무처리(NO_ACTION) 판정**(`Invoke-GissueMinimaxAttempt` 내장): 엔진(`Invoke-GissueEngine`)이
  세션 계획(베이스 URL·AK·필수 여부)을 이미 해석해 시도 함수에 오버라이드로 넘기는 구조다 →
  **CSN 특정 가능**. 같은 계획을 판정에도 넘기는 방식으로 적용. 이 함수는 잡 초기화 스크립트로
  본문이 복사되므로, 새 로직은 전부 이 함수 안 + 엔진 호출부의 인자 전달로 닫았다(외부 의존 추가 없음).
- **페이지 피드백 판정**(`page-feedback-analyze.ps1`): 도구의 CSN 이 코드에 고정(`$script:PfaCsn`)이라
  **CSN 특정 가능**. 종전 판정은 claude CLI 를 MiniMax 엔드포인트로 직접 돌리는 방식이었다.
  게이트 판정과 같은 판정 계획(`Get-GissueJudgeGairPlan`)을 재사용하되, 그 함수가 호스트 스코프의
  `$Csn` 을 읽으므로 고정 CSN 을 로컬 `$Csn` 으로 세워 호출하는 얇은 래퍼(`Get-PfaGairPlan`)를 뒀다.
  계획 해석 실패(라이브러리 부재 포함) 시에는 $null = 종전 직접 경로 유지.

## 지점별 적용 방식과 실패 계약

- 셋 다 공통: 계획 Active → env(베이스 URL·AK·함수 키 헤더) 오버라이드, `--model` 미고정, 호출 뒤 원복,
  `[GAIR]` 로그 1줄. 키 값은 로그·이력 어디에도 남기지 않는다.
- CJK-QA: 필수인데 계획이 없으면 판정을 생략하고 `[GAIR]` 로그 + 호출 실패와 같은 형태의 판정 원문
  문구로 표면화한다(기존 계약 = 판정 실패 시에도 게이트는 코멘트 없이 진행). 코멘트의 "사용 모델"
  표기는 단일 출처 `$qaModelNote` 로 바꿨다 — 직접이면 모델명, gair 경유면 경유 표기(라우터가 모델을
  정하므로 고정명을 적으면 거짓 표기가 된다).
- 무처리 판정: 필수인데 계획이 없으면 판정을 생략한다. 이 함수의 기존 실패 계약이 "판정 실패/모호 →
  기존 exit-code 판정 유지 + WARN" 이라, 생략 시에도 `$noRealActionTaken=$false` 로 같은 계약을 지킨다
  (throw 로 세션을 죽이지 않는다 — 게이트 판정에서 ok=$false 방식을 택한 것과 같은 이유).
- 페이지 피드백: 필수인데 비활성이면 판정 호출이 예외를 던진다 — 이 도구의 기존 계약이 "호출/파싱
  실패 → 건별 재시도 기록"이라, 예외가 곧 표면화 경로다(건별 격리 `Invoke-PfaItem` 이 잡아 기록).
