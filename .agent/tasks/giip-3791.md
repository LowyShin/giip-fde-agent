## 結論

SO コードに按分・分割ロジックは存在しない。加工指示書 `get_mounting_data` は `OrderLedger` を
集約せず素のまま返し（annotate/GROUP BY なし）、表示は saving_id 1 件 = 1 行。数量修正
`mobile_order_modify` は `bulk_update` のみで行を増やさない。BOM 按分は `BomPurchase` 行きで
加工指示書とは別系統。3 行分割（298.87/0.57/0.56=300.00）は受注登録時点で既に別レコードだった
可能性が最有力。確定には DEV DB SELECT + 実画面再現（人手）が必要。
