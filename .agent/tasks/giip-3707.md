## 本タスクが確定した設計判断

- **(1) 既存資産棚卸し／再利用方針**: 認証・暗号化（`fc_credentials`＋`env_settings_store` Fernet）・売上 upsert（`fc_sales`）・設定読み取り（`env_settings_runtime`）・ディスパッチ（`fc_ingest`）は**すべて既存再利用・新規実装しない**。新規に起こすのは `fetch_daily_sales` 内部の RPA ロジック（ブラウザ操作＋CSV パース）と取込ジョブ状態テーブル 1 本のみ。`verify_auth`/`fetch_daily_sales` シグネチャ維持。
- **Playwright 実行方式（2 案比較→推奨）**: **推奨 = 案 A（Python `playwright-python` を Django 管理コマンド内に閉じ込め）**。根拠=Dockerfile 変更のみで成立（Azure 変更不要・Node 同梱不要）／1 言語 1 リポで保守性高／既存シグネチャ維持に素直／案 B の唯一の優位（プロセス障害分離）は要件11 の非同期ジョブ化で代替可。案 B（Node subprocess）は条件付きフォールバック。
- **Dockerfile 同梱可否**: 可。`pip install playwright`＋`playwright install --with-deps chromium`＋`PLAYWRIGHT_BROWSERS_PATH` で成立（Azure リソース変更不要）。slim/Alpine なら `mcr.microsoft.com/playwright/python` ベース採用。本タスクでは Dockerfile を変更しない。
- **run-now 非同期化**: `budget_seconds=30` 同期は方式非依存で必ずタイムアウト → `job_id` 即時返却＋ポーリング必須。
- **アカウントロック**: 方式選定より上位の固定前提として最強明記（リトライなし・1 ログインまとめ取り・並列はアカウント間のみ）。
