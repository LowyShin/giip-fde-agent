# giip-3787 調査報告: [1/2] SO トップページ 年切替ボタンが PROD 未表示の原因調査

- **性格**: 調査・報告のみ。コード変更・DB 変更・Migration 適用・昇格(PR 作成/merge)・`restartprod` 実行は一切行っていない。
- **調査日時**: 2026-10-13 (UTC, 実システム時刻照会)
- **調査対象リポジトリ**: `LowyShin/vgt-smart-order-system`(本リポツリー外。`_tmp/vgt-smart-order-system` クローンで読み取りのみ。giip 製品レポではなく rule51 対象外)

## 結論(要約)

本件は **「ソースの昇格漏れ」でも「テナント/feature flag による表示制御」でもない**。

- 年切替ボタン(giip-3089)のソースは **`main`(PROD ブランチ)に存在**する(2026-09-26 導入、以後ずっと `main` に在る)。`dev` は `main` の祖先(`main..dev = 0`)。
- 本日 2026-10-13、`dev -> stg -> main` が **すべて昇格・デプロイ成功**済み(PR #164 -> #165 -> #166、main デプロイは 14:09:39Z success、本イシュー起票 14:35Z の **26 分前**)。
- PROD の App Service `vgt-smart-order-prod.azurewebsites.net` は giip-3089 の静的アセットを **200 で配信**(= 機能がデプロイ済み)。
- 表示可否は **データ駆動**(API が年メタデータ `chartYear` を返した時だけボタンを表示)で、STG/PROD は同一 DB 共有かつ STG で表示される → **データ条件は満たしている**。

したがって残る原因は **公開ドメイン `smart-order.online` の配信/ルーティング層**に限定される。実測では `smart-order.online` は App Service `vgt-smart-order-prod`(130.33.188.130)とは **別の Azure ASE ホスト(132.220.38.112)にルーティングされ、`/health/` を含む全パスが 404**。
これは (A) 稼働イメージの古さ(CLAIM-355: 可変タグ `:prod` が config 差分ゼロで再 pull されない)か、(B) カスタムドメイン binding / Front Door / DNS の不整合のいずれか。両者の確定には `az`(本セッションで利用不可=保留)が必要。

## 2) テナント・契約による表示制御の有無

### 事実(実測 / ソース読取)

`tesk.html` の表示ロジック(main ブランチ):
```js
function renderYearNav(){
  if (!elYnav) return;
  if (!state.chartYear){ elYnav.hidden = true; return; }   // chartYear が 0 の間は隠す
  elYnav.hidden = false;                                    // API が年を返したら表示
  elYnavYr.textContent = state.chartYear + '年';
  elYprev.disabled = !(state.chartYear > state.minYear);
  elYnext.disabled = !(state.chartYear < state.maxYear);
}
```
- 初期状態 `state.chartYear = 0` → `hidden`。売上サマリー API(`main_system:sales-summary-tesk`、`ret_last_12month` + 年メタデータ `chartYear/minYear/maxYear` を返す)の応答で `chartYear` が入って初めて `hidden=false`。
- **テナント ID・契約・feature flag・権限判定・`env_settings` 参照による出し分けは存在しない**(grep で該当なし)。可視性は純粋に「API が年メタデータを返したか」のデータ駆動。

### 推測(仮説)

- 年メタデータ `chartYear` を返す API 形(`sales-summary-tesk`)は giip-3089 で追加されたもの。もし稼働バックエンドが giip-3089 以前のイメージなら API が `chartYear` を返さず、ボタンは `hidden` のまま残る。
- ただし STG と PROD は同一 DB を共有し、STG ではボタンが表示される(=API が年を返している)ため、**DB/データ側の条件は満たされている**。よって「データが無いから隠れている」は STG 表示の事実により棄却できる。残るのは「稼働コードが古い/配信経路が別」。

## 3) PROD 未反映(= main 未反映)の他機能

### 事実(実測)

```
main..dev = 0     (dev は main に完全包含、dev は main の祖先)
stg..dev  = 0
main..stg = 0
dev..main = 1621  (main が dev より進んでいる)
dev..stg  = 1592
```
- **`main` に未反映の `dev` 差分は 0 件**。年切替ボタンと同様に「main 未反映」の状態にある機能は(少なくとも dev 基準では)**存在しない**。本日時点で dev/stg/main の内容は年切替機能を含め整合している。
- 本日のマージ鎖: dev HEAD `52fad7db`(PR#164, 22:38 JST) → stg HEAD `1b2363a2`(PR#165, 22:55) → main HEAD `e9fe269b`(PR#166, 23:05)。

### 推測(仮説)

- ブランチ topology 上、昇格鎖は完結している。したがって「PROD にソースが届いていない」線は無い。問題は配信層(稼働イメージ/ドメインルーティング)に絞られる。

- にもかかわらず公開ドメイン `smart-order.online` は別ホスト(ASE スライス)で全 404(§1)。App Service `vgt-smart-order-prod` 自体はアセット 200。

### 推測(仮説) — ランク付け

1. **(B) ドメインルーティング/binding 不整合(本セッションで直接観測した事実に最も整合)**: `smart-order.online` が giip-3089 を持つ `vgt-smart-order-prod` App Service ではなく、別の(古い/誤設定の)Azure リソース(ASE スライス 132.220.38.112)に向いている。CI は `vgt-smart-order-prod` にデプロイするが、公開ドメインはそこを指していない可能性。
2. **(A) CLAIM-355 — 稼働イメージの古さ**: 公開ドメインを配信する実体が可変タグ `:prod` を使い、config 差分ゼロのため Azure が新イメージを再 pull していない。CI 側は「デプロイ成功」と報告するが、コンテナは旧イメージを保持 → 年メタデータを返さない API → ボタン `hidden` のまま。本イシューが明示的に警戒を求めたケース。
3. **(C) ブラウザ/CDN の静的キャッシュ**: ログイン済みユーザーに古い `tesk.html`/JS がキャッシュ配信されている(弱い。ハードリロードで切り分け可能)。
