## Requirements — 단위 작업

### T1 — 조건부 디렉터리 생성과 tail 대상 정리 (요건 1)

- 321행의 `mkdir -p /work/giipAgentLinux/log && touch /work/giipAgentLinux/log/cron.log` 를 없앤다.
- 322행 `tail -F` 대상에서 giipAgentLinux 경로를 **에이전트 블록이 실제로 실행됐을 때만** 포함한다. 경로 하드코딩 금지 — `$GIIP_AGENT_DIR`(또는 블록 안에서 확정한 변수)을 그대로 쓴다.
- tail 파일 인자가 하나도 남지 않으면 `tail` 은 usage 오류로 죽는다. 320행이 `touch "$REPO_DIR/scripts/gissue/logs/cron.log"` 로 존재를 보장하므로 **이 경로는 항상 tail 대상에 남겨 둔다**(인자 0개 금지).
- `tail -F` 는 없는 파일도 받아들이지만 현재 `2>/dev/null` 로 경고가 숨겨진다. **tail 대상이 실제로 존재하는지 로그에 한 줄 남길 것**(어떤 파일이 잡혔는지).
- 에이전트를 안 쓰는 구성에서 `tail -F` 가 깨지지 않는지 **실제 기동으로 확인**한다(Test Procedure (6)).

### T2 — clone 을 잔해에 강하게 만들기 (요건 2)

- 235~241행의 분기 앞에 "`.git` 없는데 디렉터리는 있음" 분기를 추가한다.
- 원칙: **사용자 데이터가 들어 있을 수 있는 경로를 조용히 지우지 않는다.**
  - 디렉터리가 비어 있음 → 그대로 clone.
  - 디렉터리가 비어 있지 않음 → 아래 둘 중 하나를 **고르고, 무엇을 왜 했는지 로그에 남긴다.**
    - (가) **명확한 오류 + 사람이 할 조치 안내 후 기동 실패**(exit 1). 안내에는 볼륨 안에서 해당 경로를 지우는 구체적 명령까지 쓸 것.
    - (나) **退避(rename) 후 clone**: `mv "$GIIP_AGENT_DIR" "${GIIP_AGENT_DIR}.bak-<타임스탬프>"` 후 clone. 원래 경로와 시각을 로그에 남긴다.
  - 참고: 본 증상 케이스(내부에 `log/` 만 있는 잔해)는 사람이 데이터라고 볼 근거가 없지만, **자동 판정으로 삭제하지 않고** 위 절차대로 취급한다.
- `GIIP_AGENT_DIR` 은 230행에서 블록 안에서 정의된다 → 잔해 처리 분기도 블록 안에 있어야 한다.

### T3 — 토큰 fetch 실패를 삼키지 않기 (요건 3)

- 26행 `eval "$(/fetch-instance-env.sh)"` 를 종료코드를 명시적으로 검사하는 형태로 바꾼다. 예: `if ! FETCHED="$(/fetch-instance-env.sh)"; then ... fi` (stdout 만 캡처된다 — `fetch-instance-env.sh` 는 진행 메시지를 stderr 로 보낸다).
- `GIIP_INSTANCE_TOKEN` 이 설정돼 있는데 fetch 가 실패했으면 → **명확히 실패**(기본 exit 1) 하거나, 최소한 눈에 띄는 경고를 남기고 **이후 단계(에이전트 SK 해석, 스케줄러 CSN 확정)에서 같은 사실을 반복 알린다.**
- `GIIP_INSTANCE_TOKEN` 이 아예 없는 경우는 "선택 사항" 이므로 조용히 넘어가되, 요약 블록에 "fetch: 미사용" 으로 표시한다(T4).
- `fetch-instance-env.sh` 자체의 종료코드 규약(0=토큰 미설정, 1=실패)은 그대로 두어도 된다. 규약을 바꾸려면 그 파일도 함께 수정하고 사양서를 갱신한다.

## Test Procedure

이슈 원본 verify 블록을 현재 코드 기준으로 다시 쓴 것(1)(2) 의 오탐 PASS 를 제거했다).

```verify
# (1) agent log 디렉터리 생성은 에이전트 블록 안에서만 — 블록 밖 생성이 0건이어야 한다
START="$(grep -n '^if \[ "\${GIIP_ENABLE_AGENT' docker/entrypoint.sh | head -1 | cut -d: -f1)"
END="$(awk -v s="$START" 'NR>s && /^fi$/ {print NR; exit}' docker/entrypoint.sh)"
[ -n "$START" ] && [ -n "$END" ] || { echo "FAIL: 에이전트 블록 경계 못 찾음"; exit 1; }
BAD="$(awk -v s="$START" -v e="$END" 'match($0, /mkdir -p .*(GIIP_AGENT_DIR|\/work\/giipAgentLinux).*log/) { if (NR < s || NR > e) print NR }' docker/entrypoint.sh)"
[ -z "$BAD" ] || { echo "FAIL: 블록 밖 agent log mkdir 잔존(줄 $BAD)"; exit 1; }
awk -v s="$START" -v e="$END" 'NR>s && NR<e && match($0, /mkdir -p .*GIIP_AGENT_DIR.*log/) {f=1} END{exit f?0:1}' docker/entrypoint.sh \
  || { echo "FAIL: 블록 안에 agent log mkdir 없음"; exit 1; }
# tail 대상에 하드코딩 경로가 없어야 한다
! grep -q '/work/giipAgentLinux/log/cron.log' docker/entrypoint.sh || { echo "FAIL: tail 대상 하드코딩 잔존"; exit 1; }

# (2) clone 앞에 잔해 처리 분기가 실제로 있다 (무관한 'already exists' 메시지에 걸리지 않게 clone 주변으로 좁힌다)
CLONE_LN="$(grep -n 'git clone --branch main "\$GIIP_AGENT_URL"' docker/entrypoint.sh | head -1 | cut -d: -f1)"
[ -n "$CLONE_LN" ] || { echo "FAIL: clone 줄 못 찾음"; exit 1; }
sed -n "$((CLONE_LN-12)),$((CLONE_LN+4))p" docker/entrypoint.sh \
```

## PR 규칙

- 이 레포(`giip-fde-agent`): **신규 브랜치 → 커밋 → PR**. `main` 직접 push 금지. 커밋 메시지는 `.agent/rules/11_structured_commit.md` 형식.
- `giipv3`(T5-d): `giipprj` 안의 nested 레포이므로 **별도 브랜치·별도 PR**. 공유 체크아웃을 직접 수정하지 말고 전용 worktree 를 쓴다.
- 스테이징은 **내가 고친 파일 경로만** 명시한다(`git add -A` / `git add .` 금지).
- 커밋 전·후에 `git diff` 로 CSN 번호·고객 문자열이 추가된 줄에 0건인지 확인한다(rule 54).

## 하지 말 것

- `docker/entrypoint.sh` 밖의 무관한 파일을 건드리지 않는다(테스트 스크립트, 다른 cron 설정 등).
- CSN 별 분기·하드코딩을 공유 코드 경로에 넣지 않는다(rule 78).
- 검증하지 않은 것을 "확인됨" 으로 쓰지 않는다 — 못 돌린 검증은 ❌ 로 남기고 그 사실을 명시한다(rule 42).
- 사용자가 담보로 두고 있을 수 있는 볼륨 안의 경로를 조용히 삭제하지 않는다(T2).
