## Requirements — 단위 작업

### T1. 정본 스크립트에 경로 지정 파라미터 추가 (핵심)

대상: `scripts/gissue/manage-gissue-scheduler.ps1`

1. 파라미터 2개를 추가한다. **이름·관례는 `scripts/gissue/check-gissue-liveness.ps1` 와 동일**하게 한다(같은 도구 묶음의 일관성).
   - `[string]$LogDir = ''` — 로그·락 디렉터리
   - `[string]$ConfigPath = ''` — CSN 맵(`csn-projects.json`)
2. 기본값 규칙도 동일하게: `if (-not $LogDir) { $LogDir = Join-Path $Root 'logs' }` / `if (-not $ConfigPath) { $ConfigPath = Join-Path $Root 'csn-projects.json' }`
   → **인자 없는 기존 호출의 동작은 100% 동일**해야 한다(후방 호환). 하드코딩된 `$MapFile` 은 제거한다.
3. `Get-CsnMap` 은 `$ConfigPath` 를, `Get-RecentLogLines` 와 Locks 절은 `$LogDir` 를 사용한다.
   - `$MapFile` 참조는 **3곳**(대입·`Test-Path`·`Get-Content`)을 **전부** `$ConfigPath` 로 교체한다.
     일부만 남기면 정의되지 않은 변수가 남아 런타임 오류(`Cannot bind argument to parameter 'Path' because it is null`)로 죽는다
     — 2026-11-13 07:3x KST 프로토타입 검증 중 실제로 겪은 실패다.
4. `-Action Status` 출력 **맨 위**에 경로 표시를 넣는다(이슈 본문 「보완안」).
   - `로그 디렉터리: <경로>` — 지정 경로가 기본값(`$Root\logs`)이 아니면 괄호로 "이 저장소 기준이 아님(다른 경로의 로그)" 을 덧붙인다.
   - `CSN 맵: <경로>` — 같은 방식으로 기본값 여부를 표시.
   - 라벨 문자열은 위 그대로를 쓴다(완료조건 verify 블록이 이 문자열을 검사한다).

### T2. Locks 절에 PID·생존 상태 표시 (이슈 본문 「영향」 절의 실제 요구)

"락이 죽은 프로세스의 것인지"를 상태 조회만으로 판정할 수 있게 한다.

1. `scripts/gissue/lib/gissue-liveness-lib.ps1` 를 dot-source 하고 `Get-LivenessLock` 를 **재사용**한다(락 파싱·생존 판정 중복 구현 금지).
2. Locks 표에 PID·상태(`LIVE` / `STALE_DEAD_PID` / `STALE_OLD`) 컬럼을 추가한다. 죽은 PID 는 `STALE_DEAD_PID` 로 드러나야 한다.
3. 락 0건일 때의 기존 문구(`No active lock files.`)와 로그 디렉터리 부재 시의 기존 문구(`Log directory does not exist.`)는 유지한다.
