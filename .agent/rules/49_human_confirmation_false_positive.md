# 49. "사람 확인 필요" 문구 매칭 오탐 방지 — 주어와 시제를 구분한다

> **HARD RULE** — 문구 매칭으로 "사람 확인 필요"를 탐지할 때는 **주어(누가)와 시제(했다/해야 한다)**를
> 반드시 구분한다.
> 근거 giip: #2424 #2457 (2026-09-14 실측 — 완료된 작업 8건이 오탐으로 사람 대기에 묶임).

## 실측 사고

"사람 확인 필요" 류 문구를 단순 부분일치로 탐지하는 스윕이, **AI 자신의 완료 보고**를 사람 확인
요청으로 오판했다. 오판된 문장의 형태:

- `"파일을 직접 확인했다"` → `확인` 매칭 → 사람 대기 전이
- `"라이브 응답을 확인해 DONE 으로 전이한다"` → 동일
- `"사람이 확인할 수 있도록 재현 절차를 남긴다"` → 동일

결과가 특히 나쁜 이유: **규칙을 잘 지켜 검증 근거를 자세히 남긴 이슈일수록 매칭 문구가 많아져
더 자주 사람에게 떠넘겨졌다.** 규칙 준수가 벌로 돌아왔다.

## 규칙

### 1) 주어를 본다
- **AI/세션이 주어**이고 행위가 완료형이면 → 완료 보고다. 탐지 대상이 **아니다**.
- **사람이 주어**이고 행위가 미완료(요청/필요)형일 때만 → 탐지 대상이다.

### 2) 시제를 본다
- `확인했다 / 확인 완료 / 검증했다 / 재현했다` (과거·완료) → 대상 아님.
- `확인이 필요하다 / 확인 바랍니다 / 판단이 필요하다 / 결정해 주세요` (미래·요청) → 대상.

### 3) 마커를 우선한다
자유서술 문구 매칭보다 **명시적 마커가 항상 우선**한다.
사람 판단이 필요하면 세션이 [`45_gate_cap_needs_decision.md`](45_gate_cap_needs_decision.md) 의
`[NEEDS-DECISION]` 마커를 남기게 하고, 스윕은 **마커를 1순위 신호로** 쓴다.
문구 매칭은 마커가 없는 과거 이슈를 잡기 위한 보조 수단으로만 둔다.

### 4) 오탐 비용이 크다는 것을 판정에 반영한다
이 판정은 비대칭이다 — 놓치면(false negative) 다음 사이클이 다시 잡지만, 잘못 잡으면(false
positive) **완료된 작업이 사람 대기로 영구히 묶인다.** 애매하면 **잡지 않는 쪽**으로 판정한다.

### 5) 검사기는 검사 대상 수를 출력한다
스윕을 만들거나 고칠 때는 "탐지되어야 할 문장 1개 + 탐지되면 안 되는 완료 보고 문장 1개"를 실제
입력으로 넣어 두 판정을 모두 확인한다
([`42_completion_by_execution_evidence.md`](42_completion_by_execution_evidence.md)).
