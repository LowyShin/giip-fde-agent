# 45. 게이트 3회 캡 이후 처리 — `NEEDS_DECISION` + 4분기 재판정

> **HARD RULE** — 3회 캡에 걸린 이슈를 "사람 대기"로 두고 끝내지 않는다.
> 근거 giip: #2415 #2425 (2026-09-14 실측 — 3회 왕복 후 영구 정체).

## 문제

게이트(PR 완료 / Actionflow 테스트 / defer 상한 등)는 무한 왕복을 막기 위해 3회 상한을 둔다.
상한에 걸리면 `REVIEW` 로 에스컬레이션하는데, **`REVIEW` 큐는 사람이 보지 않으면 아무 일도 일어나지
않는다.** 결과적으로 "무한 왕복 방지" 장치가 "영구 정체" 장치로 동작했다.

## 규칙

### 1) 상한 도달 시 상태는 `NEEDS_DECISION`

`REVIEW`(=검증 대기)와 `NEEDS_DECISION`(=사람의 결정 대기)을 구분한다. 남은 것이 **사람의 판단
뿐**일 때만 `NEEDS_DECISION` 을 쓴다. 검증이 남았으면 `REVIEW` 다.

### 2) 매시 재판정 스윕이 4분기로 재처리

`NEEDS_DECISION` 이슈는 매 사이클 다시 열어 아래 4가지 중 하나로 분류하고, **(a)~(c) 는 세션이
직접 처리한다.** 사람에게 넘기는 것은 (d) 뿐이다.

| 분기 | 조건 | 처리 |
|---|---|---|
| (a) | 잔여 작업 0 — 이미 끝났는데 상태만 남음 | `DONE` 으로 전이 |
| (b) | 남은 게 라이브 확인뿐 | **세션이 직접 확인**하고 결과에 따라 `DONE`/`READY` |
| (c) | 구현만 남음 | `READY` 로 되돌려 착수 |
| (d) | 되돌릴 수 없는 트레이드오프 | `NEEDS_DECISION` 유지 + **예·아니오 질문 1개** |

### 3) (d) 의 질문은 예·아니오 1개로 닫는다

`"확인 바랍니다"`, `"검토 후 알려주세요"` 같은 열린 문장은 금지다. 사람이 한 글자로 답할 수 있는
형태여야 큐가 진행된다.

```
[NEEDS-DECISION] <되돌릴 수 없는 선택지 1줄 요약>
질문: <A 안>으로 진행할까요? (예 = A 안 진행 / 아니오 = B 안 진행)
- A 안: <결과와 되돌릴 수 없는 부분>
- B 안: <결과와 되돌릴 수 없는 부분>
```

### 4) 열린 상태를 확인도 안 해보고 사람에게 넘기지 않는다

플래그·상태값만 보고 에스컬레이션하지 말 것. (b) 분기가 존재하는 이유가 이것이다 — "라이브 확인이
필요하다"는 것은 사람이 필요하다는 뜻이 아니라 **세션이 아직 확인을 안 했다**는 뜻인 경우가 대부분이다.

## 이식 주의

`NEEDS_DECISION` 은 자유문자열 상태다. 대시보드에 배지가 없으면 사람 눈에 안 띌 수 있으므로,
이식 대상의 이슈 뷰가 이 상태를 표시하는지 확인하고 안 되면 그 후속을 별도 이슈로 등록한다.
