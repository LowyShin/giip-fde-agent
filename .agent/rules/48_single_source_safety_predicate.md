# 48. 안전 판정은 공용 함수 1개 (Single-Source Safety Predicate)

> **HARD RULE** — 같은 안전 판정을 두 곳에 복붙하지 않는다. 판정은 함수 1개, 호출은 여러 곳.
> 근거 giip: #2440 #2463 (판정 복붙으로 한쪽만 수정됨), #2425 (프롬프트 문단 복붙으로 한쪽만 수정됨).

## 실측 사고

### 코드 쪽 (giip #2440 / #2463)
"이 워크트리를 지워도 되는가"를 판정하는 로직이 두 함수에 복붙돼 있었다. 한쪽에만 가드를 추가한
결과, **같은 순간에 한쪽 경로는 워크트리를 보호하고 다른 쪽 경로는 삭제**했다. 두 경로 모두 "고쳤다"고
보고돼 있었기 때문에 diff 를 보기 전까지 발견되지 않았다.

### 프롬프트 쪽 (giip #2425)
스케줄러 프롬프트 템플릿에 같은 안전 문단이 **2벌** 존재했다(READY 처리 단계용 1벌, stale
IN_PROGRESS 회수 단계용 1벌). 한쪽만 고쳐져, 어느 단계를 타느냐에 따라 규칙이 적용되기도 하고
안 되기도 했다.

## 규칙

1. **판정(predicate)은 하나의 이름 붙은 함수**로 만들고, 모든 호출부가 그 함수를 부른다.
   판정 결과를 쓰는 쪽에서 조건을 "조금만 더" 추가하지 않는다 — 추가가 필요하면 함수 안에 넣는다.
2. **프롬프트/지시문의 안전 문단도 동일**하게 취급한다. 단계별로 같은 문단을 복사하지 말고,
   문단을 한 번만 정의하고 각 단계는 **"위 [안전 규칙] 그대로 따른다"** 로 참조한다.
   (이 레포 러너의 `[D]` 단계가 `[C]` 로직을 참조로 재사용하는 방식이 이 패턴의 예다.)
3. 불가피하게 2벌 이상이 남아 있는 곳이 있으면, **그 사실을 두 벌 각각의 바로 위에 주석/문장으로
   명시**한다. 예: `<!-- 주의: 같은 문단이 [D] 단계에도 있다. 고칠 때 양쪽 모두 고칠 것. -->`
4. 안전 판정을 수정하는 PR 은 머지 전에 **같은 판정 문구를 레포 전체에서 검색**해 다른 사본이
   없는지 확인한 출력을 근거로 붙인다. 사본이 있으면 같은 PR 에서 함께 고치거나 함수로 합친다.

## 이식 시 반드시 확인할 것

원본 구현(`run-gissue-claude.ps1`)의 프롬프트 템플릿은 **단계별로 유사 문단이 반복되는 구조**다.
이식하면서 안전 규칙을 넣을 때는 **템플릿 최상단(모든 단계 공통 영역)에 한 번만** 넣는다.
단계마다 넣으면 그 순간 이 사고의 재발 조건이 만들어진다.
