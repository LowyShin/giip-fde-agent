# 59. 작업과 문서의 동기화 — 문서는 지시가 없어도 작업과 함께 갱신한다

> **HARD RULE** — 코드를 바꾸고 문서를 옛 상태로 남기는 것은 미완성 작업이다.
> 배경: giipAgentWin 구조 재설계(giip #6163, 2026-11-22)에서 코드 PR만 머지되고
> 사양서(docs/SPEC_AND_CHECKLIST.md)가 옛 구조로 남아, 사용자가 직접 지적한 뒤에야
> 갱신됐다. 같은 패턴이 반복돼 사용자 직접 지시(2026-11-23)로 신설했다.

## 기본 동작 — 모든 에이전트 작업

1. **동작·구조·설정·화면이 바뀌는 작업은 같은 작업 단위(가능하면 같은 PR)에서 문서를
   함께 갱신한다.** 사용자가 문서 갱신을 말하기를 기다리지 않는다.
2. 갱신 대상:
   - **사양서**: 대상 레포의 `docs/SPEC*.md`, giipdb `docs/30_Specs`·`docs/10_Standards`,
     대상 파일에 딸린 `*_SPEC.md`·동반 `.md`
   - **유저 가이드/매뉴얼**: 사용자에게 보이는 변경이면 giipv3 `public/help` 가이드,
     웹 가이드 등 해당 매뉴얼
   - **운용 문서**: 체크리스트·README·설정 예시(`*.cfg.example` 등) 중 변경과 모순되게
     되는 문서
3. **문서 갱신이 끝나기 전에는 작업을 완료로 보고하지 않는다.** 코드만 있는 PR은
   미완성이다.
4. 문서 갱신이 불필요한 변경(동작 변화 없는 내부 리팩터 등)이면, PR 본문과 작업 보고에
   **그 이유를 명시**한다. 침묵은 선택지가 아니다.
5. 문서에 쓰는 내용은 추측이 아니라 변경된 코드·실측과 대조한 사실만 적는다. 아직
   구현되지 않은 것은 "예정"으로 구분해 적는다.

## 점검 — 작업 종료 전 자가 확인

- 이 변경으로 거짓이 되는 문장이 기존 문서에 남아 있지 않은가
- 새 파일·새 설정·새 화면이 사양서에 등장하는가
- 사용자에게 보이는 변경이면 유저 가이드에 반영됐는가
