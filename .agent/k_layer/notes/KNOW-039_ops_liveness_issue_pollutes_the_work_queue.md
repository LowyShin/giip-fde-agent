# KNOW-039 — 무소식 감지 `[OPS]` 이슈는 "작업"이 아니다 — PENDING 으로 남으면 스케줄러 큐를 오염시키고 세션 1회분을 소비한다

> 근거: 2026-11-12 CSN 70424 저장소 정비 101차 세션 실측 · 발행: 2026-11-12 · 상태: 검증됨(큐 조회 · 이슈 조회 · 상태전이 실측)

## 요지

`[OPS] gissue 처리 무소식 감지` 이슈는 **자동 생성되는 감지 기록**이다. 그런데 기본 상태가 `PENDING` 이고
코멘트가 없으므로, 러너가 작업 대상으로 삼는 우선순위 큐(`list-issues.js --csn <N> --queue`)의
`PENDING`(우선순위 1) 항목으로 **그대로 조회된다.**

⇒ 감지 건 1개마다 에이전트 세션 1회분이 "작업"으로 소모된다. 감지 건이 쌓이는 속도(6시간 쿨다운)가
스케줄러의 회차보다 빠르면, 큐는 **감지 기록으로 가득 차고** 실제 작업은 밀린다.

중복 정리로 이슈를 닫는 것만으로는 재발 방지가 아니다. **자동 감지 이슈는 큐에서 제외**되는 것이
2차 방어선이고, 근본 방어선은 "무소식 = 에피소드 1건" 모델(열린 같은 제목 이슈에 코멘트 누적 →
회복 시 코멘트 후 종료)이다.

## 실측 (2026-11-12 101차 — CSN 70424)

| 확인 지점 | 결과 |
|---|---|
| `list-issues.js --csn 70424 --queue --json` (정리 전) | 큐 36건 중 **24건이 `[OPS] gissue 처리 무소식 감지`** (전부 `PENDING`) |
| 동일 제목 열린 이슈 조회(`lib/liveness-ops-issue.js find`) | **24건**(2026-11-04 ~ 2026-11-10, 6시간 간격 누적) |
| 감지 원문 | 각 이슈 **본문**에 남아 있음(중복 정리해도 정보 유실 없음) |
| 동일 제목 조회 결과의 `cSn` | 24건 **전부 같은 CSN**(감지 기록을 적는 Ops CSN) |
| 정리 후 큐 | 12건(실제 작업 항목만 남음) |

### 주의: 이슈가 놓인 CSN 과 본문이 다루는 CSN 은 다를 수 있다

`[OPS]` 이슈는 **감지 기록을 적는 Ops CSN** 에 놓인다. 그 **본문**이 말하는 무소식 대상 CSN 은
다른 CSN 일 수 있다(예: 2026-11-04 등록분은 다른 CSN 의 3.1h 무소식만 보고했다). 그래서
"이 이슈의 `cSn` 로 대상 CSN 을 추정하지 말 것" — 본문의 `- CSN <n>: SILENT — …` 항목이 진짜 대상이다.

## 규칙

1. **자동 감지 이슈는 작업 큐의 대상이 아니다.** `[OPS]` 계열은 감지 기록이므로 큐에서 제외한다
   (제외는 **조회(큐) 계층**에만 — `list-issues.js --status <S>` 직접 조회와
   `check-gissue-liveness.ps1` 의 `find()` 경로는 영향받지 않아야 한다. 회복 시 코멘트·종료가
   계속 동작해야 한다).
2. **중복 감지 이슈는 상설 이슈로 통합한 뒤 닫는다.** 상설 이슈가 지정되면 나머지 중복은
   "상설 안내 + 중복 정리" 코멘트를 남기고 `DONE` 으로 종료한다. **감지 원문은 이슈 본문에 남아
   있으므로 중복 정리로 정보가 사라지지 않는다.**
3. **감지 기록을 "작업"으로 승격시키지 않는다.** 감지 이슈에 리뷰/테스트를 붙여 상태를 바꾸면
   실제 작업 큐와 섞인다.
4. **무소식 에피소드는 1건으로 관리한다.** 같은 침묵 구간에 여러 건이 생기면 그 자체가 결함이다
   (감지 도구의 중복 등록 경로). 발생 시 감지 경로(정본 ↔ 이식본)를 먼저 본다.
5. **공개 저장소 기록에 다른 CSN 번호를 넣지 않는다.** 큐 오염 건수·무소식 대상 CSN 목록은
   저장소·파일 경로로만 기술한다(저장소 자기 CSN 기재는 예외).

## 절차 (상설 이슈 통합 · 종료)

1. `node scripts/gissue/lib/liveness-ops-issue.js find --title-file <제목파일> --ops-csn <N>`
   → 열린 같은 제목 이슈 목록과 각 건의 실제 `cSn` 을 확보한다.
2. **쓰기 전 재검증**: 종료할 각 이슈의 `cSn` 이 작업 CSN 과 일치하는지 확인한다(다르면 건드리지 않는다).
3. 중복 건마다: "상설 이슈 안내 + 중복 정리" 코멘트(`--role` 로 역할 경로도 함께) → `DONE` 으로 종료.
4. 상설 이슈: **회복이 확인된 경우에만** 회복 코멘트(근거 = liveness 판정 결과와 측정 시각) 후 `DONE`.
   회복 판정은 감지 대상 전체(여러 CSN) 기준이다 — 한 CSN 의 회복만으로 닫지 않는다.
5. 종료 후 큐를 다시 조회해 자동 감지 이슈가 0건이고 실제 작업 항목만 남았는지 확인한다.
