# KNOW-013 — 회차 기록의 "완료" 서술은 실행되지 않은 계획일 수 있다 — 잔재는 직접 재점검해야 한다

- **근거**: CSN 70424 저장소 정비 세션 51차(죽음) → 52차(인수)

- **적용 범위**: 이 저장소의 회차 기록(work_history) 작성·인계. 다른 저장소의 회차 기록에도 같은 방식으로 적용 가능.

## 1. 현상

51차 사후 세션이 **커밋하지 못한 채 죽었다.** 남은 산출물은 워크트리에 스테이징만 된 사후 기록 4파일이었다.
그런데 그 기록 파일의 **"워크트리 회수" 절은 이미 끝난 것처럼 서술하고 있었다.**

| 기록 파일의 서술 | 52차가 실측한 사실 |
|---|---|
| "본체 워크트리 `maint-51-2330` … 실행 → **회수 완료**" | 워크트리 **2개**가 그대로 남아 있었음 |
| "**회수 후 실측**: `git worktree list` → 공유 체크아웃만" | `maint-51-2330` + `maint-51-post-0010` **2개 잔존** |
| "… `git branch -a` → … 뿐(**고아 브랜치 0건**)" | 로컬 고아 브랜치 **2개** 잔존 |
| "**이 워크트리의 회수는 … 이 세션 안에서 … 실행해 완료한다**" | 세션이 그 전에 죽어 **미실행** — 워크트리·브랜치 모두 잔존 |

52차가 실제로 `git worktree list` 를 보지 않았다면, **워크트리 2개와 로컬 브랜치 2개가 영구 잔존**했을 수 있다.
다음 회차도 같은 기록을 읽고 "이미 정리됐다"고 넘어가면 끝까지 안 지워진다.

## 2. 원인

**"실행 결과"와 "실행할 계획"이 같은 어조로 적혀 있다.**

- 기록을 쓰는 시점에 세션은 **정리 실행 직전**이었다. 그때의 머릿속 상태는 "곧 끝난다"였고,
  서술도 그 전제를 따랐다 — "실행하면 이렇게 된다"를 "실행했다"로 적었다.
- `rule 42`(완료 판정은 실행 결과로만)는 **판정자**의 규칙이다. 기록 **작성자**에게
  "아직 실행 안 한 걸 완료로 쓰지 말라"는 대칭 규칙이 없어, 작성 순간에는 규칙이 걸리지 않는다.
- 게다가 `git worktree list` · `git branch -a` 같은 확인 명령의 **출력은 기록에 붙지 않는다.**
  붙은 건 "회수 완료"라는 **요약**뿐이라, 다음 회차는 요약을 믿고 재확인하지 않게 된다.

## 3. 교정 (52차)

### 3-1 규칙 73 방식으로 정정 (과거 기록은 고쳐 쓰지 않는다)

- 해당 절 **앞에** `> 정정(날짜, 세션): …` 블록을 삽입했다.
- 무엇이 *계획*이었고 무엇이 *실측*이었는지 구분해 적었다.
- 원 기록 문장은 지우지 않았다 — "이랬다고 적혀 있었고, 실측은 이랬다"가 남아야 다음 사람이 판단한다.

### 3-2 잔재는 직접 회수

- 정본 도구 `scripts/gissue/cleanup-worktrees.ps1 -RepoPath <공유체크아웃> -OnlyPath "<경로>" -MinIdleMinutes 0`
  를 **공유 체크아웃 cwd 에서** 실행해 워크트리 2건을 **항목별** 회수했다(rule 47).
- **회수 후 실측 4종**을 새로 떠서 기록에 남겼다:
  `git worktree list` → 공유 체크아웃 1개만 · `git branch -a` → 고아 브랜치 0건 ·
  `git ls-remote --heads origin` → 원격 `main` 1건 · `git stash list` → 0건.

### 3-3 기록 작성 규칙 (다음 회차용)

- **"실행 완료"를 적기 전에 그 명령의 실제 출력을 먼저 떠서 붙인다.** 못 떴으면 "예정"으로 적는다.
- "회수 완료 · 실측: …" 같은 **요약형 완료 문구**는 금지. 요약은 실측을 대체하지 못한다.
- 세션이 죽을 위험이 있는 지점(장시간 명령 직후·PR 생성 직후·정리 실행 직후)에서는
  **커밋을 먼저 하고** 기록은 커밋된 상태 기준으로 적는다.

## 5. 다음 세션에 대한 인계

- **회차 기록을 읽을 때 "완료" 라는 단어만 믿지 말고, 그 항목의 현재 상태를 명령으로 다시 떠라.**
  특히 워크트리·브랜치·stash·PR 은 `git`/`gh` 로 직접 확인한다.
- 이번 회차의 확인 명령 4종:
  `git worktree list` · `git branch -a` · `git ls-remote --heads origin` · `git stash list`.
- 상속(인계)한 산출물은 **커밋하기 전에 정본 게이트를 그 워크트리에서 직접 돌려** 통과를 확인한다.
  (51차 세션의 파일이므로 "51차가 이미 돌렸을 테니" 는 근거가 아니다 — rule 42.)
