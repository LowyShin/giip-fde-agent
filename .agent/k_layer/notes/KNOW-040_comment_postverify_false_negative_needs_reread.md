# KNOW-040 — 코멘트 사후검증 `verified:false` 는 "등록 실패"가 아니다 — 저장된 내용을 다시 읽어 확인한다

> 근거: 2026-11-12 CSN 70424 저장소 정비 101차 세션 실측 · 발행: 2026-11-12 · 상태: 검증됨(재조회로 확인)

## 요지

`scripts/gissue/lib/post-comment.js`(→ `comment-api.js` 의 `postCommentVerified`)는 코멘트를 등록한 뒤
**재조회해서 원문과 대조**하고, 결과로 `verified:true|false` 를 돌려준다.

`verified:false` 의 뜻은 **"검증에 실패했다"가 아니라 "검증하지 못했다"** 다. 사유는 등록 응답이
200 이고(등록 자체는 성공) 但 **재조회 목록에서 방금 만든 코멘트를 특정하지 못했거나**, 재조회 자체가
살패한 경우다. 특히 **기존 코멘트가 이미 여러 건 달린 이슈**에서는 "POST 전후 목록 차집합"으로
방금 만든 코멘트를 특정하는 방식이 실패하기 쉽다.

실측(2026-11-12 101차): 상설 이슈(기존 코멘트 2건)에 회복 코멘트를 등록하자
`{"success":true,"verified":false,"cSn":null,"attempts":1}` 이 반환되었다. 등록 직후 **별도 조회**로
확인한 결과 — 코멘트는 **정상 등록**되어 있었고 한글 본문도 그대로였으며 `loadedRole` 값도 채워져 있었다.

## 규칙

1. **`verified:false` 를 "등록 실패"로 단정하지 않는다.** 곧바로 재조회로 내용을 확인한다.
   코멘트가 실제로 있으면 **성공**으로 처리한다.
2. **재조회로 확인할 항목은 3가지다.** ① 코멘트 본문이 원문과 일치(한글·이모지 깨짐 없음)
   ② `loadedRole` 이 채워졌는지(역할 경로를 `--role` 로 넘겼을 때)
   ③ 이슈의 제목·본문(status-only PUT)이 보존되었는지.
3. **깨짐이 확인될 때만** 삭제·재등록 경로를 쓴다(무한 재시도 금지).
4. **등록 성공 + 검증 실패** 를 보고할 때는 "등록됨(사후검증 미수행)" 라고 정확히 적는다.
