# 되돌림 판정의 단위는 의뢰 항목이다 (giip 4334)

## 핵심

`review-done-audit.ps1` / `pr-gate-sweep.ps1` 은 REVIEW/DONE 이슈를 READY 로 되돌리는 근거로
"대응 PR 이 있고 머지됐는가"를 썼다. 의뢰는 보통 복수 항목이고 문서 등록·외부 설정·조사처럼 코드 변경이 아닌
항목이 섞여 있어서, PR 유무 하나로 전체 완료를 뒤집으면 **정상 완료가 반복해서 되돌려진다**.
게다가 코드/비코드 분류(`Get-IssueClassification`)가 키워드 근사치(최신 코멘트에 `.ps1`·`배포` 같은 단어
하나)라 오분류가 곧 오판 되돌림이었다. 오판이 나올 때마다 예외 패치(`[NO-PR-REASON]` 마커, 사람확인 문구
정확일치, 템플릿 오탐 우회)가 쌓여 룰이 더 복잡해졌다.

## 설계 원칙 (구현: `scripts/gissue/gissue-audit-lib.ps1` 의 체크리스트 구역)

1. **판정 단위 = 의뢰 항목.** 항목마다 충족/미충족/판정불가 + 근거. PR 머지는 `code` 항목의 증거일 뿐이다.
2. **세 값을 구분한다.** 증거가 없어 모르는 것(판정불가)과 증거가 반대인 것(미충족)을 섞으면 "모름"이
   되돌림으로 변한다. 판정불가만 있으면 되돌리지 않고 보류(NEEDS_DECISION)한다. 판정 호출 실패·형식 불일치도
   "모름"이므로 전이하지 않는다.
3. **코멘트 없는 전이 금지를 코드로 강제한다.** 말(규칙)이 아니라 `Set-IssueStatusAudit` 가드가 막는다.
4. **되돌림 코멘트는 다음 세션의 작업 범위다.** 미충족 항목을 `- [ ] (C<번호>)` 형식으로 명시하고,
   스케줄러 지시문이 그 항목만 이어받게 한다. 코멘트 형식과 파서(`Get-LatestUnmetChecklistItems`)는 한 쌍이다.
5. **별도 게이트를 증거로 흡수한다.** scope/comment/VERIFY/보고형 대조를 각각 되돌림 권한을 가진 게이트로 두면
   서로 다른 근거로 같은 이슈를 번갈아 되돌린다. 하나의 판정에서 항목별 증거로 쓴다.
6. **새 판정은 Shadow 로 먼저.** 기본 모드는 기록만 하고(코멘트·상태 쓰기 없음), Live 는 명시적으로만 켠다.
   롤아웃 전에 구·신 병행 비교(`compare-checklist-vs-legacy.ps1`)를 한다.

## 구현 중 실측한 함정

- 경량 판정 모델(haiku)은 "각 줄은 `ITEM|...` 로 시작" 지시에도 가끔 `<라벨>|code|MET|항목|근거` 로 낸다 →
  파서가 `ITEM` 접두사에만 의존하면 항목 0건이 되어 "분해 실패"로 처리된다. 2·3번째 필드가 kind/판정 어휘와
  정확히 일치할 때만 접두사 없는 줄도 인정하도록 했다(설명문 오인 방지).
- 되돌림 횟수 집계는 코멘트의 **마커 포함 여부**로 센다. 체크리스트 코멘트 본문에 다른 게이트의 마커 원문을
  넣으면 그 코멘트가 다음 회차 카운트를 부풀린다 → 집계 키 `checklist` 는 `CHECKLIST-REVERT` 만 센다
  (KEEP/HOLD 는 되돌림이 아니므로 제외).
- 비교 스크립트의 PR 증거는 되돌림 당시가 아니라 조회 시점 상태라 신룰에 관대하게 작용할 수 있다. 결과 보고 시
  이 한계를 함께 적는다.
