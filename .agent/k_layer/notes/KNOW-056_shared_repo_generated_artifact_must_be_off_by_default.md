## 요지

공용(공유) 레포에서 **봇이 만든 파일을 레포 루트에 쓰고 `git add`/`commit`/`push` 하는 모듈**은
**환경변수 스위치가 없으면 반드시 켜져 있었다.** 그 결과 ① 파일이 공개 레포 트리에 들어가고
② PR 단계가 "pre-existing uncommitted changes on base branch" 로 거부되며 ③ 사람이 만든
staged 상태(PR 에 포함되지 않은 파일)가 남아 **다음 세션의 작업을 막는다.**

이것은 "파일이 생겼더라" 수준이 아니다. **생성 경로가 커밋·푸시까지 이어지면, 그 파일은
자동으로 "레포의 일부"가 되어 다른 사람의 작업을 막는 장애물로 변환된다.** 그래서 대응은
"파일 삭제"가 아니라 **생성 경로 자체를 기본 끔으로 바꾸는 것**이어야 한다.

## 실측 (giip 4211)

- 발생: 2026-10-27T02:16Z. `slack-bot` 이 `LOWY_ACTION_DASHBOARD.md` 를 레포 루트에 생성.
  사용자는 이 파일을 nako_test 세션에서 삭제하지 않았다 — 삭제 대상으로 인식하지 못한 것이
  아니라 **지정된 경로(레포 루트)에 대한 쓰기 금지 규칙**이 있었기 때문.
- 결과: 파일이 `A`(staged 신규) 상태로 남아 PR 단계가 "pre-existing uncommitted changes" 로
  거부(giip 4207).
- 구조적 사실: `slack-bot/dashboard.js` 의 `BASE_DIR` 는 `path.join(__dirname,'..')` 로
  **저장소 루트를 고정**한다. 즉 "어느 디렉터리에서 봇을 띄웠는지"와 무관하게, **그 모듈을
  가진 저장소의 루트**에 파일을 쓴다. → cwd 를 바꾸는 것으로는 막을 수 없고, **모듈 자체의
  기본값**을 바꿔야 한다.

## 규칙 (다음 세션이 지킬 것)

1. **공용 레포에 쓰는 생성형 산출물은 기본 끔** — 켜려면 명시적 opt-in(`SLACKBOT_DASHBOARD=on`
   처럼 값이 명시된 환경변수)을 요구한다. "값이 없으면 동작"이 아니라 **"값이 명시돼야 동작"** 이
   기본이다.
2. **CLI 수동 실행은 예외로 남긴다** — 사람이 직접 `node dashboard.js` 를 실행하는 것은 의도된
   동작이므로 `force` 경로로 스위치와 무관하게 동작하게 둔다. 오염의 원인은 **자동 호출**이지
   사람이 일부러 실행하는 동작이 아니다.
3. **가드는 진입부 한 곳에 둔다** — `refreshDashboard()` 진입부에서 판정하면 호출부
   (`handlers.js` 등)는 그대로 두고도 모든 경로가 막힌다. 호출부마다 조건을 붙이면 새 호출 경로가
   생길 때마다 빠뜨린다.
4. **`.gitignore` 등록을 게이트로 쓴다** — 켜진 환경에서 파일이 생겨도 실수로 stage 되지 않게
   한다. "파일을 지우는 코드"는 규칙 64(코드 보존) 취지에 어긋나므로 넣지 않는다.
5. **가드가 실제로 막는지 회귀 테스트로 고정한다** — 미설정 / `1` / `true` / `off` 는 파일
   생성·git 호출 0건, `on` 만 진행. **"코드가 존재한다"만 확인하지 말고 "파일이 안 생겼고 git 이
   불리지 않았다"를 단언한다.** (giip 4211 검증: `node --test slack-bot/tests/dashboard.test.js`
   → 6 pass / 0 fail. 수정 전에는 기본 끔 검증 4건이 FAIL 했다.)
6. **배포본과 개발본은 별개 파일로 산다** — 같은 파일이 여러 저장소에 각각 존재하면 한쪽에
   가드를 넣고 다른 쪽에는 넣지 않은 상태가 정상적으로 발생한다. **"배포본에도 가드가 있다"는
   판단을 커밋 그래프 조상 관계로 추론하지 말고, 배포된 파일을 직접 읽어 확인한다.** (giip 4211
   9차 세션 실측 정정: 배포본(lowyworkenv) `slack-bot/dashboard.js` 에는 `isDashboardEnabled` 가
   0건이었다 — giip-fde-agent 사본에만 존재.)
