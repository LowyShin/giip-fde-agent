# KNOW-041 — 완료 게이트의 되돌림이 자동 감지 이슈를 다시 큐에 넣어 "큐 오염"을 재발시킬 수 있다

> 근거: 2026-11-12 CSN 70424 저장소 정비 102차 세션 실측 · 발행: 2026-11-12 · 상태: 검증됨(직접 재측정)

## 요지

두 게이트가 서로를 무한히 부른다.

① **의뢰 체크리스트 판정**(review-done-audit)이 미충족을 근거로 이슈를 `DONE → READY` 로 되돌린다.
② `READY` 는 경과 60분 뒤 작업 큐(`list-issues.js --csn <N> --queue`)에 들어간다.
③ 자동 감지로 생성된 `[OPS]` 이슈는 **"작업"이 아니므로** 큐에서 소비되면 안 된다.

남은 블로커가 **이 저장소 밖(러너가 실제 실행하는 경로 — 이 저장소 밖의 다른 소관)** 이면 ①이 매 회차
반복되고 ②가 큐를 계속 오염시킨다. 결과적으로 **되돌림 → 큐 재진입 → 소비** 의 루프가 생긴다.

⇒ 교훈 2가지.

1. **큐 오염 상태는 이슈 본문에 적힌 스냅샷이 아니라, 쓰기 시점에 직접 재측정해서 판단하라.**
   (`liveness-ops-issue.js find` + `list-issues.js --queue` 를 그 시점에 다시 돌린다.)
2. **되돌림 사유가 이 저장소 밖의 미해결 항목이면, 큐 오염을 먼저 멈추는 방어선(큐 조회 계층 제외)이 필요하다.**
   큐 제외가 구현되기 전까지는 되돌림 자체를 반복시키지 않는 것이 방어선이다.

## 규칙

1. **큐 오염은 "이슈 본문에 적힌 스냅샷"으로 판정하지 않는다.** 본문 스냅샷은 그 시점의 상태이고
   되돌림으로 60분 뒤엔 큐에 재진입한다. **쓰기 직전에** 큐를 다시 조회해 실측한다.
2. **되돌림을 곧바로 되돌리지 않는다(되돌림의 되돌림).** 이 저장소 밖 소관의 미해결 항목은
   이 CSN 안에서 충족될 수 없다 → 되돌림 사유가 그런 항목이면 `DONE → READY` 되돌림이 반복된다.
   되돌림이 막히면 큐에 들어가는 빈도가 떨어지지 않으므로 **먼저 큐 오염을 멈춘다.**
3. **큐 제외는 조회(큐) 계층에만 적용한다.** `list-issues.js --status <S>` 직접 조회와
   `check-gissue-liveness.ps1` 의 `find()` 경로는 영향받지 않아야 한다 —
   회복 코멘트·종료 경로가 살아 있어야 한다.
4. **감지 이슈를 "작업"으로 승격시키지 않는다.** `[OPS]` 는 감지 기록이지 작업 항목이 아니다.
5. **공개 저장소 기록에 다른 CSN 번호를 넣지 않는다.** 큐 오염 건수·대상 CSN 목록은
   경로·파일명·제목으로만 기술한다(저장소 자기 CSN 기재는 예외).

## 절차 (쓰기 시점 재측정 → 판단)

1. `node scripts/gissue/lib/liveness-ops-issue.js find --title-file <제목파일> --ops-csn <N>`
   → 열린 같은 제목 이슈 목록과 각 건의 실제 `cSn` 을 확보한다.
2. `node scripts/gissue/list-issues.js --csn <N> --queue --json`
   → **지금 이 시점의** 큐 길이와 그 안의 `[OPS]` 건수를 센다.
3. 두 값을 합쳐 "감지 이슈가 큐에 몇 건 있는지"를 **현재값**으로 판단한다(이슈 본문 스냅샷이 아님).
4. 큐에 `[OPS]` 가 있으면 위 규칙 3(조회 계층 제외) 방향으로 방어선을 두거나,
   되돌림 재발 원인(저장소 밖 미해결 항목)을 먼저 멈춘다.
