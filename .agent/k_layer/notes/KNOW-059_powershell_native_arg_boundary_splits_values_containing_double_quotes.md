# PowerShell → 네이티브 인자 경계: 값에 큰따옴표가 있으면 인자가 쪼개진다

> 실측 근거: giip 6620 (2026-11-28) · 회귀 테스트 `scripts/gissue/tests/test-followup-title-file.ps1`

## 무엇이 일어나는가

Windows PowerShell 5.1 이 네이티브 실행 파일(node 등)에 인자를 넘길 때, **값 안에 큰따옴표(`"`)가 들어 있으면
그 값이 두 인자로 쪼개진다.** Windows 명령줄 재구성 단계에서 따옴표가 인자 구분자로 취급되기 때문이다.

실측 (제목 값에 큰따옴표가 들어 있는 경우):

| 전달 방식 | node 이 받는 argv |
|---|---|
| `& node x.js --title <값>` | `argv[2] = '[후속] slack-bot 이 소켓은'` / `argv[3] = '연결됐는데 … (원본 giip #5141)'` |
| `& node x.js --title-file <경로>` | 값이 쪼개지지 않고 **통째로** 전달됨 |

消费 측이 `--title` 의 **바로 다음 토큰 하나만** 읽으면(register-issue.js 가 그렇다), 등록된 제목은 첫 조각으로 잘리고
뒤쪽 표식(`(원본 giip #NNNN)`)이 통째로 사라진다. → 실제로 isn 6606 의 저장 제목이 정확히
`'[후속] slack-bot 이 소켓은'` 로 잘려 있었다(원본 제목의 큰따옴표 앞에서 잘린 결과와 문자열 일치).

## 규칙

1. **값에 따옴표·공백·한글이 들어갈 수 있는 인자는 네이티브 인자로 직접 넘기지 않는다.** UTF-8 **파일**로 넘긴다
   (`--title-file` / `--content-file` 패턴 — 같은 저장소의 `run-gissue-claude.ps1` 타임 초과 분해 경로가 이미 쓰던 방식).
2. 이 저장소에서 이미 파일 경유를 쓰던 호출부를 **새로 만들지 않는다** — `register-issue.js` 는 `--title-file` 을 지원하고,
   형제 러너의 사본도(giip 4117, 한글 제목이 시스템 코드페이지로 깨지는 문제) 이미 같은 해법을 쓰고 있었다.
   **같은 파일 안에서 한 경로만 파일 경유이고 다른 경로만 인자 직접 전달이면 그게 곧 이 결함의 원인이 된다.**
3. 회귀 테스트는 **기대 PASS 1건 + 기대 FAIL 1건**을 실제로 만들어 둔다 — 이 결함의 회귀 테스트는
   (A) 인자 경계 재현(표식 소실 확인) + (B) 파일 경유 정합성(원본과 한 글자도 다름) 두 축으로 고정한다.

## 함정

- **증상이 조용하다.** 등록은 "성공"한다(200). 제목만 조용히 잘린다 → 원본 이슈 번호 표식이 사라진 채로 후속 체인이
  이어지고, 사람이 나중에 보면 "무슨 이슈에서 나온 건지"를 잃는다. 그래서 표식 소실 자체가 회귀 테스트의
  관찰점이 되어야 한다.
- **깨진 제목은 2차 손실을 만든다.** 잘린 제목으로 다시 캐리오버를 만들면 접두가 두 번 붙고(`[후속] [후속] …`),
  잘린 문자열이 고정에 가까워진다(재현 입력으로 굳어버린다).
- **PowerShell 7 에서도 안전하지 않다.** 따옴표 규칙이 버전·셸·경로에 따라 달라질 수 있으므로, 판정에 의존하지 말고
  **구조적으로 경계를 제거**(파일 경유)한다.
