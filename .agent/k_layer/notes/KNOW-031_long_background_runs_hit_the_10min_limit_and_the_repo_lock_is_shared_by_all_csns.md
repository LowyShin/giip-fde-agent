# KNOW-031 — 긴 백그라운드 실행은 10분 기본 제한에 걸리면 "중단"이다, 그리고 저장소 락은 CSN 전체가 공유한다

> 근거: 2026-11-03 저장소 정비 82·83차 세션 실측 · 발행: 2026-11-03 · 상태: 검증됨(실측)

## 요지

저장소 정비 세션이 길게 걸리는 두 작업이 **에이전트 하네스의 백그라운드 실행 기본 제한(10분)** 에 걸렸다.

1. **82차** — `scripts/gissue/run-repo-gates.ps1` 전체 실행을 백그라운드로 띄웠으나 **10분 제한에 kill** 되어
   완주하지 못했다. 82차 기록은 이 실행을 **"성공도 실패도 아닌 미완주"** 로 적었다.
2. **83차** — `scripts/repo-lock.ps1 -Acquire` 대기가 **1차 시도에서 10분 제한에 kill** 됐다.
   (다른 CSN 세션이 락을 점유한 상태였음)

→ **kill 된 실행은 성공도 실패도 아닌 "미완주"** 다. 종료 코드도 요약도 없는 실행을
성적처럼 기록하면 안 된다(rule `42_completion_by_execution_evidence.md`).

## 교훈

1. **긴 백그라운드 작업은 제한 시간을 명시적으로 올려 재기동한다** — 기본값 10분이 아니라
   필요한 만큼 지정한다. 83차는 2차 시도에서 `-WaitMinutes 40` · 백그라운드 timeout 45분으로
   재기동해 락 획득에 성공했다.
2. **중단된 실행의 출력은 증거가 아니다** — 종료 코드도 요약도 없다. 기록에는 **"미완주"** 로 적고,
   동일 코드를 CI 가 돌리는 경우 **CI 결과를 대신 인계**한다.
   82차의 전체 게이트 실행은 미완주로 남었고, 같은 게이트를 돌리는 PR CI(Repo Gates)가
   그 회차의 PR #353 을 **success** 로 통과시켰다(run `41602003538`).
3. **저장소 락(`scripts/repo-lock.ps1`)은 CSN 전체가 공유하는 전역 자원**이다.
   매시 :07 에 여러 CSN 세션이 동시에 시작하면 **대기 시간이 수십 분**이 될 수 있다.
   "내 CSN 이 다른 CSN 때문에 40분 대기"는 정상 동작이다.
4. **홀더는 세션이 죽어도 최대 1시간 락을 붙든다** — 홀더 PID 가 `Start-Sleep 3600` 센티널이면
   세션의 부모 프로세스가 종료된 뒤에도 **센티널이 살아 있는 동안 락은 유지**된다.
   → 세션이 죽은 것처럼 보여도 **락을 빼앗지 않는다**.
5. **남의 락을 지우지 않는다** — 재시도와 대기만 한다(rule `48_single_source_safety_predicate.md`).
   락 파일은 `.agent/locks/lowyworkenv-repo.lock` 이며 `.gitignore` 대상(로컬 런타임 상태)이다.
