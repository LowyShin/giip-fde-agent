# KNOW-022 — PR 머지는 이슈 측 쓰기(코멘트·상태 전이) 실행의 증거가 아니다

> 근거: giip 4411 · 발행: 2026-11-02 (저장소 정비 66차) · 상태: 검증됨(실측)

## 요지

**저장소 변경이 PR 로 머지되었다는 사실은, 그 세션이 이슈 측 쓰기(정정 코멘트·상태 전이)까지 실행했다는
증거가 아니다.** 저장소 act 와 이슈 act 는 서로 다른 실행 단위이고, 하나가 끝났다는 사실로 다른 하나가
끝났다고 서술하면 문서에 거짓이 남는다. 세션이 끊기면 남은 act 는 "미실행"이 된다.

## 사례 (2026-11-02 저장소 정비 65차 → 66차)

- 65차 세션의 저장소 산출물은 정상 머지되었다 — `gh pr view 341` → state `MERGED`,
  createdAt `2026-11-01T20:19:25Z`, mergedAt `2026-11-01T20:27:10Z`,
  merge 커밋 `c7aa8c90e083a49f49b5137ef6b684252da8d2b3`, head `chore/csn70424-maint65-20261102-0430`.
- 그러나 그 세션이 4411 에 남기기로 한 **정정 코멘트**와 **READY 상태 전이**는 실행되지 않았다.
  66차 세션 실측 — `get-issue.sh 4411 70424` → status `PENDING`, 코멘트 2건
  (최종 regdate `2026-11-01T18:06:01Z`). 65차 회차의 코멘트는 존재하지 않는다.
- 그런데 65차가 남긴 **공개 문서 2건**은 그와 반대로 서술하고 있었다.
  - `.agent/work_history/20261102_0430_csn70424_repo-maintenance.md` §상태 전이 —
    "65차는 READY 로 복귀시켰다"
  - `docs/WHATS_NEW.md` `## 2026-11-02` 65차 항목 — "정정 코멘트과 함께 READY 복귀 했습니다"
- → **KNOW-013 유형의 재발**(실행하지 않은 계획을 완료로 서술)이 이번에는 PR 로 머지된 공개 문서에 남았고,
  다음 회차 세션의 [H] 판정 근거가 될 뻔했다.

## 판정 규칙

1. **PR 머지 ≠ 이슈 측 쓰기 완료.** 세션 기록에 "전이했다"고 적기 전에 전이 API 응답을 확인한다.
   응답을 확인하지 못했으면 "실행하지 않음"으로 적는다.
2. **세션이 끊기면 남은 act 는 "미실행"이다.** 다음 세션이 그 세션의 문서를 읽을 때 문서 서술과
   DB 실체(코멘트 목록·이슈 상태)를 대조한다. 근거는 코멘트·상태 조회이지 문서가 아니다.
3. **실행되지 않은 전이는 되돌리지 않는다.** 남은 act 를 실행하거나, [H] 범위에서 READY 까지만 복귀한다.
   `DONE`·`TESTED` 전이는 [G] 게이트 전용이다(giip 1244 사고).
4. **기록에는 "예정/실측"을 구분해 적는다.** 저장소 act 와 이슈 act 가 모두 끝난 뒤에만 "완료"로 적는다.

## 적용

- 저장소 정비 세션([0]/[E]/[F]/[H])은 저장소 act 와 이슈 act 를 각각 별도 act 로 기록한다.
- 세션 기록에 상태 전이·코멘트 등록을 적을 때는 응답 확인 여부를 함께 적는다.
  (예: "READY 전이 실행 — 응답 확인" / "미실행 — 세션 종료로 끊김")
