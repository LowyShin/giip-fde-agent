# KNOW-034 — 외부 모델 단계를 결정적 규칙 뒤에 삽입할 때의 설계 규칙

> 근거: 2026-11-04 세션 실측 (Jev 의도 분류 어댑터 구현 · `slack-bot/intent.js`) · 발행: 2026-11-04 · 상태: 검증됨(회귀 테스트 22 케이스)

## 요지

결정적 규칙(LLM 호출 0회)으로 끝나던 분류기에 **외부 모델 단계를 하나 끼워 넣을 때** 지켜야 할 규칙 7가지.
특정 기능이 아니라 **단계 삽입 자체의 설계 규칙**이므로 다른 분류기에도 그대로 적용된다.

1. **스위치 기본 OFF** — 끈 상태에서 기존 판정 결과가 **동일**해야 한다. 새 단계는 "켜져 있을 때만 쓰는 것".
2. **임계값은 확정값처럼 쓰지 않는다** — 제안값의 자리표시자로 취급하고 값은 **호출 시점**에 읽는다(모듈 로드 시점 상수 금지) · 전부 환경변수로 덮어쓸 수 있게 한다.
3. **폴백 체인** — 새 단계의 실패·모호함·저신뢰는 에러가 아니라 **"다음 단계"**. 기존 경로가 끊기면 안 된다.
4. **전송 계층은 주입 가능하게** — 네트워크 계층을 `opts` 로 주입하면 회귀 테스트가 **네트워크 0** 으로 돌아간다.
5. **외부 응답을 완성된 값으로 취급하지 않는다** — 필드가 없으면 추정하지 말고 **보수값(0.0/실패)** 으로 둔다.
6. **판정 로그는 원문 금지** — 마스킹 통과본의 해시·길이만 남긴다. 새 저장소를 만들지 않는다.
7. **호출부 시그니처는 깨지 않는다** — 새 인자는 **선택 인자**. 호출부 변경은 최소로.

## 사례 (2026-11-04, `slack-bot/intent.js`)

원래 ① 결정적 규칙 → ③ 기존 LLM(`claude -p`) 2단이었다. 그 사이에 ② Jev 단계를 넣으며 위 7개를 적용했다.

**① 스위치** — `JEV_INTENT_ENABLED` 는 `1|true|yes|on`(대소문자 무시)일 때만 동작, 미설정=꺼짐.
판정 함수가 호출 시점에 읽는다(`intent.js:138`). 꺼져 있으면 ② 를 통째로 건너뛰므로 판정이 현행과 동일하다
(회귀 테스트 `slack-bot/tests/intent-jev.test.js:101` "스위치 꺼짐: Jev 전송 0회 + LLM 결과가 그대로 반환" 가 고정).
스위치가 꺼져 있어도 **판정 로그는 남는다**(로그는 판정 결과에 영향 없음).

**② 임계값** — `JEV_INTENT_T_HI`/`P_HI`/`P_LO` 기본 0.8/0.7/0.3 은 **사양 제안값**이며 확정값이 아니다.
코드·문서·로그 어디에도 "확정"으로 적지 않는다. `jevNumberEnv()` 로 **호출 시점**에 읽는다(`:143` · 사용처 `:296`~`:298`).
모듈 로드 시점 상수로 잡으면 값 변경에 재시작이 필요하다.

**③ 폴백 체인** — 각 실패는 즉시 `null`(=다음 단계)을 돌려준다(`:244`~`:256`).
`switch_off` · `no_gateway_url` · `no_sk` · `jev_error` · `jev_http_<status>` · `jev_not_success` ·
`jev_ambiguous`/`jev_bad_intent` · `jev_no_confidence` · `jev_low_confidence`.
`null` 은 "판정을 확정하지 않음" 이고 호출부가 ③ 으로 내려간다 — 신규 단계가 기존 경로를 대체하지 않는다.

**④ 전송 계층 주입** — `opts.jevRequest || postForm`(전송 함수 교체 가능) · `opts.spawn || spawnAsync`(기존 LLM 호출 교체).
그래서 테스트는 네트워크를 건드리지 않는다. 게이트웨이 URL·키를 코드에 하드코딩하지 않고
**접속 주소는 환경변수 하나가 유일한 경로**다. 내부 helper 는 Node 내장 `http`/`https` 만 쓴다(상위 API 모듈 `require` 는 순환 위험).
**클라이언트는 본문을 자르지 않는다**(`:207`~`:210`) — 길이 제한은 게이트웨이 규약의 몫이고, 임의로 자르면 서버 값과 로컬 로그가 어긋난다.

**⑤ 보수적 파싱** — `intent` 가 `task`/`question` 이 아니면 고쳐 쓰지 않는다(`:275`~`:278`) ·
`intent_confidence` 가 유한한 수가 아니면 다음 단계(`:281`~`:282`) · 확률 필드 누락은 **0.0**(`:285`~`:286`).
0.0 은 "파일 변경 없음" 쪽으로만 흐르므로 task 로 오분류되지 않는다.
라우팅 표에 없는 값(조회 여부 플래그 등)은 **로그에만** 남기고 판정에는 쓰지 않는다(`:306`~`:307`).

**⑥ 판정 로그** — 저장 위치는 **봇 프로세스 stdout(`console.log`)** , 새 저장소 없음(`:311`~`:336`).
형식: `[Bot] intent-classify source=rule|jev|llm|fallback intent=… reason=… jevIntent=… jevConf=… jevRfc=… jevLookup=… jevEngine=… latencyMs=… maskedLen=… textHash=…`.
**원문은 남기지 않는다** — `maskString` 통과본의 sha256 앞 8 hex 와 길이만 남긴다.
`source` 로 **어느 단계가 결정했는지**를 남겨야 나중에 임계값을 다시 튜닝할 수 있다.
안내문은 **③ 가 실제로 실패했을 때만** 붙는다(`:339`~`:350`) — ③ 가 성공해서 question 이 나온 건 정상 동작이다.

**⑦ 호출부** — `classifyRequest(text, workDir = BASE_DIR, opts = {})` 의 `opts` 는 선택 인자라 기존 2인자 호출이 그대로 돌아간다.
호출부 3곳(`slack-bot/handlers.js:1399`·`1432`·`1474`)은 인자 추가만 했고 **`isForceTaskCmd` 선평가 순서도 그대로**다
(명시적 의사는 모델 판정이 뒤집어도 안 된다).

## 적용

- 결정적 경로 뒤에 외부 모델(다른 AI 게이트웨이·분류기·검증기)을 단계로 추가할 때.
- 사양서 "제안값" 을 코드 기본값으로 옮기면서 **확정으로 오해될 위험**이 있을 때.
- 외부 호출을 추가하면서 회귀 테스트를 **네트워크 0** 으로 유지하고 싶을 때.
- 외부 응답 필드가 누락·모호할 때 **값을 지어내지 않는 규칙**이 필요할 때.
- "판정 결과가 어디에도 안 남아 재튜닝할 수 없다" 는 문제를 만났을 때(단, **새 저장소를 만들지 않고** 기존 로그 경로 사용).
