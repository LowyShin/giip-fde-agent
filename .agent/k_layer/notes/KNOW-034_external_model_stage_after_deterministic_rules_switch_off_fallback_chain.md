# KNOW-034 — 외부 모델 단계를 결정적 규칙 뒤에 삽입할 때의 설계 규칙

> 근거: 2026-11-04 세션 실측 (Jev 의도 분류 어댑터 구현 · `slack-bot/intent.js`) · 발행: 2026-11-04 · 상태: 검증됨(회귀 테스트 22 케이스)

## 요지

결정적 규칙(LLM 호출 0회)으로 끝나던 분류기에 **외부 모델 단계를 하나 끼워 넣을 때** 지켜야 할 규칙 7가지.
요지만 보면 "특정 기능"이 아니라 **추가 단계 삽입 자체의 설계 규칙**이므로, 다른 분류기·다른 외부 호출에도 그대로 적용된다.

1. **스위치는 기본 OFF** — 새 단계를 켜지 않은 상태에서는 기존 판정 결과가 **바이트 단위로 동일**해야 한다.
   새 단계는 "있으면 쓰는 것"이 아니라 "켜져 있을 때만 쓰는 것"이다.
2. **임계값·提案값은 확정값처럼 쓰지 않는다** — 코드에 넣는 기본값은 *제안값의 자리표시자*로 취급하고,
   "미확정"을 코드·문서·로그 어디에도 확정으로 남기지 않는다. 값은 **호출 시점**에 읽는다(모듈 로드 시점 상수 금지).
3. **폴백 체인은 "실패"가 아니라 "다음 단계"** — 새 단계의 실패·모호함·저신뢰는 모두 정상적인 경로이며,
   그때마다 기존 경로로 내려간다. 새 단계 때문에 기존 경로가 끊기면 안 된다.
4. **전송 계층은 주입 가능하게 만든다** — 네트워크 계층을 함수 인자(`opts`)로 주입 가능하게 하면
   회귀 테스트가 **네트워크 0**으로 돌아간다. 같은 방식으로 기존 LLM 호출도 `opts.spawn` 로 주입한다.
5. **외부 응답을 "완성된 값"으로 취급하지 않는다** — 필드가 없으면 추정하지 말고 **보수값(0.0 / 실패)** 으로 두어
   다음 단계로 내려간다. "분류값을 지어내면 봇이 그 값을 권위로 신뢰한다."
6. **판정 로그는 원문을 남기지 않는다** — 마스킹 통과본의 해시·길이만 남긴다. 로그 저장소를 새로 만들지 않는다.
7. **호출부 시그니처는 깨지 않는다** — 새 인자는 **선택 인자**로 추가한다. 기존 2인자 호출이 그대로 돌아가야
   하위 호환이 유지되고, 호출부 변경은 최소로 남는다.

## 사례 (2026-11-04, `slack-bot/intent.js`)

Slack 봇의 의도 분류는 원래 ① 결정적 규칙 → ③ 기존 LLM 분류기(`claude -p`) 2단이었다.
그 사이에 ② 외부 모델(Jev) 단계를 넣으면서 위 7개를 적용했다.

### ① 스위치 기본 OFF — 끈 상태는 기존과 동일

```
JEV_INTENT_ENABLED      1|true|yes|on (대소문자 무시) 일 때만 동작. 미설정 = 꺼짐.
```

- 판정 함수는 `jevEnabled()` 로 **호출 시점**에 읽는다(`slack-bot/intent.js:138`).
- 꺼져 있으면 ② 를 통째로 건너뛰고 ① → ③ 으로 가므로 **판정 결과가 현행과 완전히 동일**하다.
  회귀 테스트 "스위치 꺼짐: Jev 전송 0회 + LLM 결과가 그대로 반환"(`slack-bot/tests/intent-jev.test.js:101`)이 이 불변식을 고정한다.
- 스위치가 꺼져 있어도 **판정 로그는 남는다**(로그는 판정 결과에 영향 없음).

### ② 임계값은 "확정"이 아니라 "제안값의 자리표시자"

```
JEV_INTENT_T_HI / JEV_INTENT_P_HI / JEV_INTENT_P_LO   기본 0.8 / 0.7 / 0.3
```

- 기본값은 사양서의 **제안값**을 그대로 복사한 것이고, 평가가 끝나기 전에는 확정값이 아니다.
  그래서 **코드·문서·로그 어디에도 "확정"으로 적지 않는다.** 문서에는 "제안값이며 확정값 아님"을 명시한다.
- 세 값은 `jevNumberEnv()` 로 **호출 시점**에 읽는다(`slack-bot/intent.js:143`, 사용처 `296`~`298`).
  모듈 로드 시점에 상수로 잡으면 프로세스 수명 동안 값이 못 바뀐다 → 설정 바꾸려면 재시작해야 한다.
- **환경변수로 덮어쓸 수 있어야 한다.** 평가 결과가 나오면 코드 수정 없이 값만 바꿔 확정할 수 있다.

### ③ 폴백 체인 — 실패도 정상 경로

새 단계는 아래 순서로 즉시 `null`(=다음 단계로)을 돌려준다(`slack-bot/intent.js:244`~`256`).

| reason | 조건 | 다음 |
|---|---|---|
| `switch_off` | 스위치 꺼짐 | ③ |
| `no_gateway_url` | 접속 주소 환경변수 미설정 | ③ |
| `no_sk` | 해당 채널에 계정(=키) 없음 | ③ |
| `jev_error` | 전송 예외·타임아웃 | ③ |
| `jev_http_<status>` | HTTP 상태가 200 아님 | ③ |
| `jev_not_success` | 바디가 없거나 `success !== true` | ③ |
| `jev_ambiguous` / `jev_bad_intent` | `intent` 가 `task`/`question` 이 아님 | ③ |
| `jev_no_confidence` | `intent_confidence` 가 유한한 수가 아님 | ③ |
| `jev_low_confidence` | 신뢰도가 임계값 미만 | ③ |

`null` 을 돌려주는 쪽이 **판정을 확정하지 않는다**는 뜻이고, 호출부가 ③ 으로 내려간다.
신규 단계가 **기존 경로를 대체하지 않고 앞에 붙는다**는 것이 폴백 체인의 본질이다.

### ④ 전송 계층 주입 — 네트워크 0 테스트

```
분류기 안의 전송:  opts.jevRequest || postForm      // postForm 은 로컬 helper(내장 http/https 만 사용)
기존 LLM 호출:    opts.spawn || spawnAsync
```

- `opts.jevRequest` 로 **전송 함수를 통째로 갈아끼울 수 있다** → 회귀 테스트는 실제 네트워크를 건드리지 않는다.
  같은 방식으로 `opts.spawn` 로 기존 LLM 호출도 갈아끼운다.
- 게이트웨이 URL·키·환경을 코드에 하드코딩하지 않는다. **접속 주소는 환경변수 하나가 유일한 경로**다.
- 내부 전송 helper 는 Node 내장 `http`/`https` 만 쓴다(외부 패키지 추가 0). 상위 API 모듈을 여기서 `require` 하면
  순환/결합 위험이 생기므로 **작은 로컬 helper** 를 두는 편이 낫다.
- **클라이언트는 본문을 자르지 않는다.** 길이 제한은 게이트웨이 쪽 규약의 몫이며,
  클라이언트가 임의로 자르면 서버가 받은 값과 로컬 로그가 어긋난다(`slack-bot/intent.js:207`~`210`).

### ⑤ 외부 응답은 보수적으로 파싱

- `intent` 가 `task`/`question` 이 아니면 `ambiguous` 로 분류하고 **값을 고쳐 쓰지 않는다**(`:275`~`:278`).
- `intent_confidence` 가 유한한 수가 아니면 `jev_no_confidence` → 다음 단계(`:281`~`:282`).
- `requires_file_change` 등 확률 필드가 없으면 **0.0**(보수값)으로 둔다(`:285`~`:286`).
  0.0 은 "파일 변경 없음" 쪽으로만 흐르므로 **task 로 오분류되지 않는다.**
- 응답에 없는 필드로 **새로운 판정 규칙을 만들지 않는다.** 라우팅 표에 없는 값(예: 조회 여부 플래그)은
  **로그에만** 남기고 판정에는 쓰지 않는다(`:306`~`:307`).

### ⑥ 판정 로그 — 원문 금지, 저장소 추가 금지

```
[Bot] intent-classify source=rule|jev|llm|fallback intent=… reason=… jevIntent=… jevConf=…
        jevRfc=… jevLookup=… jevEngine=… latencyMs=… maskedLen=… textHash=…
```

- **저장 위치는 봇 프로세스 stdout(`console.log`)** — 새 저장소를 만들지 않는다(`:311`~`:336`).
- **원문은 남기지 않는다.** 마스킹(`maskString`) 통과본의 sha256 앞 8 hex 와 길이만 남긴다.
  해시를 남기는 이유는 "같은 입력이 같은 판정을 냈는지" 비교할 수 있게 하기 위해서이며,
  원문을 남기면 로그가 곧 데이터 유출이 된다.
- `source` 에는 `rule`(결정 규칙)·`jev`·`llm`(③ 성공)·`fallback`(③ 실패)이 들어간다.
  **어느 단계가 결정했는지**를 모르면 나중에 임계값을 다시 튜닝할 수 없다.
- 안내문은 **③ 가 실제로 실패했을 때만** 붙는다(`:339`~`:350`). ③ 가 성공해서 `question` 이 나온 경우는
  분류가 성공한 것이므로 안내문을 붙이지 않는다 — 붙이면 정상 동작을 오류처럼 보이게 한다.

### ⑦ 호출부 시그니처 유지

```
classifyRequest(text, workDir = BASE_DIR, opts = {})   // opts 는 선택 인자
```

- 새 인자를 **선택 인자**로 넣었기 때문에 기존 2인자 호출 `classifyRequest(text, workDir)` 은 그대로 동작한다.
- 호출부는 3곳(`slack-bot/handlers.js:1399`·`1432`·`1474`)이고, 각각 `opts` 를 붙이는 것만 했다.
  **`isForceTaskCmd` 선평가 순서는 그대로**다 — 명시적 의사는 모델 판정이 뒤집어도 안 된다.
- 회귀 테스트 "isForceTaskCmd 선평가 유지: 호출부 3곳 소스 수준 회귀 가드"가
  호출부 3곳이 계속 `isForceTaskCmd` 로 먼저 가드되는지 **소스 수준에서** 검사한다.

## 판정 규칙

1. **새 단계를 넣을 때 스위치 기본값은 OFF.** 켜진 상태를 기본으로 하면, 평가 전 파라미터가 곧 실트래픽이 된다.
   끈 상태에서 기존 판정이 동일한지 테스트로 고정한다.
2. **기본값을 넣되 그것이 확정값이 아님을 코드 밖(문서·로그)에서 명시한다.** 그리고 전부 환경변수로 덮어쓸 수 있게 한다.
3. **새 단계의 모든 실패 경로가 기존 경로로 이어지는지 확인한다.** "실패" 를 에러로 취급하지 말고 "다음 단계" 로 취급한다.
4. **판정 근거를 남기되 원문은 남기지 않는다.** 어느 단계가 왜 결정했는지(단계·사유·지연·해시)만 남긴다.
5. **외부 응답 필드가 없으면 추정하지 않는다.** 보수값(0.0) 또는 실패로 두고 다음 단계로 내려간다.
6. **호출부는 최소 변경.** 새 인자는 선택 인자로, 호출부는 인자 추가만.

## 적용

- 기존 결정적 경로 뒤에 외부 모델(다른 AI 게이트웨이·분류기·검증기)을 단계로 추가할 때.
- 사양서의 "제안값" 을 코드 기본값으로 옮기면서 **확정으로 오해될 위험**이 있을 때.
- 외부 호출을 추가하면서 회귀 테스트를 **네트워크 0** 으로 유지하고 싶을 때.
- 외부 응답을 소비할 때 **값을 지어내지 않는 규칙**이 필요할 때(요청이 누락된 필드·모호한 라벨).
- "판정 결과가 어디에도 안 남아서 다시 튜닝할 수 없다" 는 문제를 만났을 때
  (단, **새 저장소를 새로 만들지 않고** 기존 로그 경로를 쓴다).
