# 러너 105분 자기 마감과 커밋 단계의 순서 (2026-11-04 90차 실측)

## 핵심

1. **러너는 "저장소 정비" 세션도 105분에 끊는다.** 이슈 처리 중이면 2시간 초과 처리 규칙(`KNOW-024`·rule 84)으로 분할·종료하지만,
   **처리 중인 이슈가 없는 저장소 정비 세션은 조기 마감 경로**로 들어간다 — 마감시각을 **지금**으로 앞당기고 잡 워커를 `Stop-Job` 으로 종료시킨다.
2. **커밋·PR 은 세션의 마지막 단계이므로, 마감 전에 도달하지 못하면 전부 사라진다.**
   측정·기록 작성에 예산을 쓰면 **항상 커밋 전에 잘린다.** → **커밋·push 를 기록 작성보다 먼저** 하는 순서가 정답이다.
3. **"사망 원인"은 하나가 아닐 수 있다.** 86·87차는 엔진 모델명 인식 오류(`[claude-code:unrecognized_model]`)로 죽었고,
   88·89차는 엔진 오류 없이 진행됐으나 **여전히 커밋 전에 죽었다.** 앞 회차의 원인 진단을 그대로 믿으면 다음 회차가 같은 지점에서 죽는다.

## 실측 (2026-11-04, 90차 — CSN 70424 저장소 정비)

**증거 1 — 러너 상수**: `scripts/gissue/run-gissue-claude.ps1:272` → `$RunTimeoutMin = 105`
(주석: "Windows ExecutionTimeLimit 은 '내부 정리마저 실패했을 때'의 최후 안전망으로 2시간 유지").

**증거 2 — 저장소 정비 경로의 조기 마감**: `run-gissue-claude.ps1:1726-1731` —
`Invoke-GissueOvertimeCheck` 는 **처리 중인 이슈가 없으면**(저장소 정비 단계)
`$r.Deadline = Get-Date` 로 마감시각을 **즉시 앞당기고** `return $false` 한다.
이어 본 루프 `elseif ((Get-Date) -gt $r.Deadline)` → **`Stop-Job $r.Job`** → `Complete-Run` (`:1757-1760`).

**증거 3 — CSN 70424 로그의 세션 START→종료 패턴**(`scripts/gissue/logs/gissue_csn70424.log`):

| START | 종료 기록 | 소요 |
|---|---|---|
| 2026-11-03 21:08:08 | 22:52:09 `[OVERTIME] 과시간 감지 — run 기준 (프로세스 105.1분)` | **105분** |
| 2026-11-03 23:25:45 | 2026-11-04 02:12:49 `stale lock 제거 — 시간초과(3h)` | — |
| 2026-11-04 02:12:49 | 03:52:02 `[OVERTIME] ... (프로세스 105분)` → 04:21:15 `stale lock 제거` | **105분** |
| 2026-11-04 04:21:15 | 90차 세션 시작 | — |

로그의 OVERTIME 판정 직후 단계 줄은 항상 **`[ENGINE] MiniMax 1차 시도 실패(exit=-1) → 재시도 1회`** 까지이며,
그 뒤는 잡 출력이 회수되지 않는다("잡 출력은 이슈 세션 안의 엔진 출력까지 담지 못한다").

**증거 4 — 4회 연속 미커밋**: 86·87·88·89차가 작업 기록과 What's New 갱신을 워크트리 `maint-86-2108` 에 남기고
**커밋 0건 · PR 0건 · 원격 ref 0건** 으로 종료됐다. 90차가 계승해 커밋·push·PR 로 마감했다
(`KNOW-013` "기록의 완료 서술은 실행되지 않은 계획일 수 있다" 의 4회 연속 재현).

## 어떻게 적용하는가

1. **계승 잔재가 있으면 그것부터 커밋·push 한다.** 측정·[H] 검증보다 **먼저**.
   기록(작업 기록 파일·What's New·정정 블록)은 **그 뒤에** 쓰고 2번째 커밋으로 추가한다.
   → 세션이 다시 잘려도 이전 회차 산출물이 원격에 남는다.
2. **커밋은 PR 로 올린다**(main 직접 push 금지). 그 다음 CI 를 기다리고 머지한다.
   **"push 했으니 끝" 으로 끝내지 않는다** — `gh pr list --state all --head <branch>` 로 PR 성립을 확인한다(`KNOW-015`).
3. **사망 원인을 앞 회차의 기록에서 그대로 가져오지 않는다.** 로그·러너 코드로 **직접 재확인**한다(3번 항목).
4. 러너 자체의 수정은 **이 저장소 밖**(lowyworkenv)이라 하지 않고, **사람 판단용 후속**으로 남긴다.
