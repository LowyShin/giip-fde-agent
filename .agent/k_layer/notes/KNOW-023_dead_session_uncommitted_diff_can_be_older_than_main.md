# KNOW-023 — 죽은 세션 워크트리의 미커밋 diff 는 main 보다 오래됐을 수 있다

> 근거: 2026-11-02 저장소 정비 68차 세션 실측 (work_history 20261102_1008) · 발행: 2026-11-02 · 상태: 검증됨(실측)

## 요지

**죽은 세션 워크트리에 남아 있는 미커밋 diff 를 "미완료 작업" 으로 읽어 커밋하면 회귀 PR 이 된다.**
워크트리는 그 세션이 마지막으로 체크아웃한 시점의 스냅샷이므로, 그동안 `main` 이 갱신되었으면
그 diff 는 **오래된 스냅샷**이 된다. 이관(계승) 전에 `main` 기준으로 **staleness 를 먼저 대조**한다.

두 번째 교훈 — **정본 도구(`cleanup-worktrees.ps1`) 의 삭제 판정은 "브랜치명에 머지된 PR 이 있는가" 기준**이라,
죽은 세션 산출물이 **다른 브랜치의 PR 로 이관**되면 그 브랜치는 영구히 `MANUAL-REVIEW` 로 남는다.
정본 도구 판정을 우회해 강제 삭제하지 말고 사유를 기록한다(rule 48 판정 단일화).

## 사례 (2026-11-02 저장소 정비 68차)

죽은 세션 워크트리 `maint-62-2331`(브랜치 `chore/csn70424-maint64-20261102-0250`, HEAD `b10cf06`)에
미커밋 변경 2건이 남아 있었다. "미완료 산출물이니 보존·이관" 으로 읽기에는 약했다. 그런데
`origin/main` 기준으로 대조한 결과:

| 파일 | `git -C <worktree> diff origin/main -- <파일>` 결과 |
|---|---|
| `docs/HISTORY.md` | diff **0건** |
| `docs/WHATS_NEW.md` | **1 insertion / 4 deletions** |

삭제되는 4줄은 **이미 `main` 에 머지된 65차·66차 항목**(PR #341·#342·#343)이었다.
→ 즉 이 워크트리의 미커밋 내용은 `main` 보다 **오래된 스냅샷**이며, 그대로 커밋하면
**`main` 의 최신 기록을 되돌리는 회귀 PR** 이 된다. **이관 대상이 아니다.**

동일 회차의 다른 사례 — `liveness-4411`(브랜치 `feat/gissue-liveness-4411`, HEAD `399ee8b`)은
PR #340 이 MERGED(merge 커밋 `b10cf06`, mergedAt `2026-11-01T16:38:47Z`)이고
`git diff --stat b10cf06 399ee8b` 출력이 **빈 것**(내용 동일)이라 남는 고유 내용이 없었다 →
정본 도구로 회수(삭제)했다. **머지 여부와 내용 동일성은 별개로 확인해야 한다.**

`maint-62-2331` 은 정본 도구 판정 `MANUAL-REVIEW`(머지 PR 없음) 였고 68차는 **삭제하지 않고 보류**했다.
보류 사유: 64차 산출물은 **다른 브랜치의 PR(#341)로 이관**되어 이 브랜치에는 머지 PR 이 없어
영구히 `MANUAL-REVIEW` 로 남는다. 정본 도구 판정을 우회해 강제 삭제하지 않는다.

## 판정 규칙

1. **이관 전에 staleness 를 먼저 대조한다.**
   `git -C <worktree> diff origin/main -- <파일>` 로 "이 변경이 `main` 에 없는 진짜 신규 내용인가" 를 본다.
2. **삭제(+)만 나타나고 `main` 쪽에만 있는 내용이 사라진다면 = 오래된 스냅샷 → 이관 대상이 아니다.**
   커밋하면 `main` 의 최신 기록을 되돌리는 회귀가 된다. 워크트리를 삭제할지 판단은 별개다.
3. **"미커밋이 있다"는 사실 자체로 보존·이관 근거를 삼지 않는다.** `main` 대비 무엇이 남는지가
   이관 판단의 기준이다. 전체 커밋/변경 통계가 아니라 **파일 단위 diff** 로 본다.
4. **정본 도구 판정을 우회해 강제 삭제하지 않는다.** `MANUAL-REVIEW` 면 사유를 기록하고 보류한다
   (rule 48 — 안전 판정은 공용 함수 1개).

## 적용

- 죽은 세션 워크트리를 계승할 때: 워크트리 diff 를 `origin/main` 과 먼저 대조하고,
  **오래된 스냅샷이면 이관 대상이 아님**을 기록에 남긴다.
- 워크트리 회수 시: "머지 PR 이 있는가"(도구 판정)와 "머지된 내용과 동일한가"(스냅샷 대조)를
  **둘 다** 확인한다. 도구 판정만으로 "내용 없음"을 단정하지 않는다.
