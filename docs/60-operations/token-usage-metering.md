# 토큰 사용량 계측·과금 구조와 스크립트 우선 스케줄러 설계

> 상태: 설계 (2026-11-16). 구현은 §5의 순서로 나눠 진행한다. 1단계(기록 선행)는 giip 5398로 구현한다.
> 관련: 스케줄러 본체 비AI 리포트 원칙은 [hourly-issue-scheduler.md](hourly-issue-scheduler.md) §17이 정본이며, 이 문서는 그 원칙을 토큰 사용량 기록으로 확장한다.

## 1. 배경 (실측)

- 현재 스케줄러는 CSN별 엔진 세션이 이슈 처리 전체를 담당한다. 실측하면 엔진 호출 1회당 평균 약 16만 토큰이 계수되고, 그중 약 98%가 캐시 읽기다. 실행 1건이 수백 회의 호출로 이뤄지므로 호스트당 하루 1억 토큰 단위, 전체로는 하루 10억 토큰 단위까지 간다.
- 사용량은 지금 어디에도 구조적으로 남지 않는다. 엔진이 실행된 호스트의 로컬 세션 기록에만 있고, 플랫폼(GIIP)에서는 보이지 않으며, CSN별 귀속도 과금도 불가능하다.
- 외부 콘솔의 총량은 캐시 읽기를 액면 그대로 합산한다. 따라서 과금 설계는 총량이 아니라 토큰 분류별 원형 기록에서 출발해야 한다.

## 2. 원칙

1. **기록은 AI를 거치지 않는다.** 사용량 기록도 스케줄러 본체(순수 코드)가 엔진 호출 전후로 직접 남긴다 (§17의 본체 비AI 원칙과 동일). 엔진이 사용량 한도로 죽는 바로 그 실행에서도, 죽기 전까지의 사용량은 남아야 한다.
2. **원형 저장, 정책은 집계 시점에 적용한다.** 토큰은 4분류(fresh input / cache creation / cache read / output)로 나눠 원형 그대로 저장한다. 과금 가중과 단가는 집계 단계의 정책(요율표)으로만 적용한다. 정책을 바꿔도 과거 기록으로 다시 계산할 수 있어야 한다.
3. **CSN 단위 귀속.** 모든 사용량 레코드는 CSN에 귀속된다. 귀속할 수 없는 호출(공용 작업 등)은 별도 버킷으로 명시하고, 조용히 어느 CSN에 붙이지 않는다.
4. **fail-open.** 기록 실패가 스케줄러 본 실행을 멈추지 않는다 (기존 kvs-report 규약과 동일).

## 3. 구조 A — 사용량 기록과 과금

### 3.1 캡처 지점

- 엔진 호출 래퍼 한 곳에서 캡처한다. 판단 호출은 §4.2의 `claude -p --output-format json` 규약으로 통일하므로, 응답 JSON의 usage 블록(input_tokens, cache_creation_input_tokens, cache_read_input_tokens, output_tokens, model)이 1차 소스다.
- 세션형 엔진 호출이 남는 구간은 호스트 로컬 세션 기록(JSONL)의 usage 합산으로 보완한다. 합산은 호스트 로컬 스크립트가 수행하고 결과만 전송한다. 원본 세션 기록 자체를 플랫폼으로 보내지 않는다.

### 3.2 레코드 — tKVS factor `scheduler_token_usage`

기존 `scripts/gissue/lib/kvs-report.ps1`의 와이어 형식(KVSPut, kType='lssn', kKey=LSSN)을 그대로 쓰고 factor만 추가한다. CSN별 실행 종료 시 1건, 엔진별 내역을 배열로 포함한다.

```json
{
  "event": "token_usage",
  "csn": "<csn>",
  "runId": "...",
  "at": "yyyy-MM-dd HH:mm:ss",
  "hostname": "...",
  "ips": ["..."],
  "engines": [
    { "model": "MiniMax-M3.1-Flash", "calls": 0, "freshIn": 0, "cacheCreate": 0, "cacheRead": 0, "out": 0 },
    { "model": "MiniMax-M3",         "calls": 0, "freshIn": 0, "cacheCreate": 0, "cacheRead": 0, "out": 0 },
    { "model": "claude-opus-4-8",    "calls": 0, "freshIn": 0, "cacheCreate": 0, "cacheRead": 0, "out": 0 }
  ]
}
```

- 전송 함수는 kvs-report.ps1에 `Send-GissueTokenUsageRecord`를 추가해 기존 패턴(전송 포트 교체 가능한 테스트 구조, fail-open, Write-Host 로그 규약)을 재사용한다.
- 기록 시점은 CSN별 종료 리포트(`scheduler_run_report`)와 같은 지점이다. 실행이 비정상으로 끝나도 그때까지 누적된 사용량을 보낸다 (원칙 1).

### 3.3 집계와 과금 (플랫폼 측)

- 일 단위 롤업: CSN × 일자 × 모델 × 분류 합계. 월 단위 청구 라인: 롤업 × 요율표.
- 요율표는 플랫폼 설정으로 둔다 (모델 × 분류 → 100만 토큰당 단가). 단가 변경은 설정 변경으로만 하고 코드 변경을 요구하지 않는다.
- 캐시 읽기의 과금 가중은 요율표의 분류 단가로 표현한다 (예: 캐시 읽기 단가를 fresh input 단가의 1/10로 설정). 가중 값 자체는 정책 결정 사항으로 §6에 분리한다.
- 조회는 CSN별 월 합계, 모델별 내역, 분류별 내역을 기본으로 한다.

## 4. 구조 B — 스크립트 우선 스케줄러

### 4.1 단계 분리

현재의 "CSN 세션 전체를 엔진이 처리"하는 구조를 3단계로 나눈다.

1. **스크립트 단계 (엔진 없음)** — 이슈 목록 조회, 직전 상태와의 diff, 규칙으로 떨어지는 상태 전이 판정, 정형 코멘트 게시, PR·게이트 상태 확인, tKVS 기록. 규칙으로 판정 가능한 것은 전부 여기서 끝낸다.
2. **판단 게이트 (엔진 호출은 여기서만)** — 스크립트 단계가 "판단 필요"로 분류한 항목만 모아, CSN당 실행 1회당 최대 수 회의 `claude -p` 호출로 처리한다.
3. **실행 단계 (엔진 없음)** — 판단 결과를 기존 API로 실행한다 (전이, 코멘트, 등록). 실행 결과의 검증도 스크립트가 한다.

### 4.2 판단 호출 규약

- 호출 형식: `claude -p --output-format json` (비대화형 1회성). 세션을 유지하지 않는다. 거대한 누적 컨텍스트가 생기지 않는 것이 절감의 본체다.
- 입력은 델타만 준다. 이슈 전체 목록이나 히스토리가 아니라, 판단에 필요한 항목의 본문·최근 코멘트·규칙 발췌만 패키징한다. 호출당 입력 상한을 둔다 (초기값 32K 토큰, 초과 시 항목을 나눈다).
- 출력은 구조화 JSON으로 받는다 (항목별 결정: action, 근거). 스크립트가 스키마를 검증하고, 검증에 실패한 항목만 재호출하거나 사람 판단 큐로 넘긴다.
- 엔진 선택은 게이트 안에서만 일어난다. 기본 엔진은 MiniMax M3.1 Flash다 (MiniMax 사용 전반의 기본값 규칙과 동일 — 기본은 Flash, 코드 작업과 민감한 내용은 M3로 올린다). 최상위 판단(게이트 재검증 등)은 Claude를 쓴다. 엔진을 바꿔도 스케줄러 구조는 바뀌지 않는다.
- 모든 판단 호출은 §3.1의 래퍼를 통과한다. 호출 즉시 사용량이 CSN에 귀속되고 기록된다.

### 4.3 기대 절감 구조

- 호출 수: 실행당 수백 회 → 판단 호출 수 회 이하.
- 호출당 컨텍스트: 누적 세션(약 16만 토큰, 캐시 읽기 반복) → 델타 패키지(상한 수만 토큰).
- 총량의 약 98%를 차지하던 캐시 읽기는 "같은 컨텍스트의 반복 재읽기"가 사라지므로 구조적으로 축소된다. 절감률은 도입 후 실측으로 확정한다 (§5).

## 5. 도입 순서와 검증

1. **기록만 먼저.** §3.2 레코드와 전송 함수를 추가한다 (동작 변경 없음). 호스트별 로컬 합산, 플랫폼 기록, 외부 콘솔 총량의 3자 대조로 계측 정확도를 먼저 확정한다.
2. **집계와 과금.** §3.3 롤업·요율표·청구 라인을 플랫폼에 만든다. 과금 개시는 §6 정책 결정 이후로 한다.
3. **판단 게이트 시범.** §4의 단계 분리를 CSN 1곳에 적용해 처리 품질(전이 오류, SKIP 사유 패턴)과 사용량을 전후 대조한다.
4. **확산.** 시범 검증이 끝난 뒤 전 CSN으로 넓힌다. 기존 세션형 경로는 시범이 끝날 때까지 유지해 롤백 경로를 남긴다.

**호스트 로컬 합산 호출 규칙.** `scripts/gissue/lib/token-usage.ps1` 의 `Get-GissueTranscriptTokenUsage` 는 `-SinceUtc` 를 **UTC 기준**으로 해석한다. ISO8601 문자열(`...Z`)·네이티브 DateTime 리터럴·UTC/Local 어느 `DateTime.Kind` 로 넘겨도 **같은 instant** 로 정규화되어(`ConvertTo-GissueUtcDateTime`) 동일한 집계가 나온다. 정규화 없이 `Kind` 가 섞이면 `DateTime` 비교가 원시 tick 으로 이뤄져 시간창이 UTC 오프셋만큼 밀리고, **최근 구간이 0건으로 조용히 사라진다**(오류 아님 → "측정값 0" 으로 오독된다). 회귀 테스트 `scripts/gissue/tests/test-token-usage.ps1` 가 이 동치를 고정한다.

## 6. 정책 결정 사항 (구현과 분리)

- 분류별 과금 단가와 캐시 읽기 가중 (요율표 초기값).
- 과금 개시 시점과 소급 적용 여부.
- 귀속 불가 호출(공용 인프라 작업)의 배분 규칙.
